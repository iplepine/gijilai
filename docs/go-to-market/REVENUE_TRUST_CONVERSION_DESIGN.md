# 수익화·신뢰·전환 상세 설계

Status: Proposal
Date: 2026-05-02

## 1. 결론

`₩2억~₩12억/년` 매출 구간을 목표로 본다면 지금의 우선순위는 기능 추가가 아니라 `무료 아이 리포트에서 유료 지속관리로 넘어가는 이유`를 선명하게 만드는 것이다.

추천 상품 구조는 다음과 같다.

```text
무료 아이 리포트
→ child-only 리포트
→ 전체 분석 확장
→ 상담 체험
→ 월 구독
→ 실천 기록 누적
→ 후속 상담
```

단품 유료 리포트는 바로 기본 상품으로 넣지 않는다. 현재 결제 정책은 `건별 결제 폐지, 월 구독만 운영`이고, 기질아이의 장기 가치는 리포트 단발 판매보다 `상담 → 실천 → 기록 → 다음 상담`의 반복 루프에서 나온다. 단품 리포트가 필요하다면 `첫 결제 진입장벽을 낮추는 실험 상품`으로만 별도 검증한다.

## 2. 매출 목표를 제품 지표로 환산

현재 월 구독가가 `12,000원/월`이므로 연 매출 목표를 평균 유료 구독자 수로 환산하면 다음과 같다.

| 연 매출 목표 | 월 매출 목표 | 필요 평균 유료 구독자 |
|--------------|--------------|------------------------|
| ₩2억 | 약 ₩1,667만 | 약 1,389명 |
| ₩6억 | ₩5,000만 | 약 4,167명 |
| ₩12억 | ₩1억 | 약 8,333명 |

이 표는 매출 가능성을 보장하는 예측이 아니라 운영 기준선이다. 실제 목표 관리는 아래 지표로 한다.

| 단계 | 핵심 지표 | 초기 판단 기준 |
|------|-----------|----------------|
| 유입 | `landing_viewed → login_success` | 메시지와 타깃 적합성 |
| 활성화 | `login_success → survey_flow_completed(child)` | 무료 진단 진입 장벽 |
| 신뢰 | `report_viewed → report_primary_cta_clicked` | 리포트가 다음 행동을 만드는지 |
| 전환 | `pricing_viewed → payment_started → payment_completed` | 가격/가치 납득 여부 |
| 유지 | `consult_started → practice_log_created → followup_consult_started` | 구독 유지 이유 |
| 방어 | 환불률, 해지 사유, CS 응답 지연 | 신뢰 손상 여부 |

운영 가드레일:

- 월 구독 전환은 `리포트 구매 욕구`가 아니라 `다음 상담이 더 정확해진다`는 기대에서 만들어야 한다.
- 광고 집행 전에는 최소한 `report_viewed → pricing_viewed → payment_started` 퍼널이 실제 수집되어야 한다.
- 전환율보다 먼저 봐야 할 것은 `환불/해지 사유`다. 육아 앱은 신뢰 훼손이 장기 매출을 바로 깎는다.

## 3. 상품 구조

### 3-1. 기본안: 구독 중심 구조

| 구분 | 제공 가치 | 목적 | 결제 유도 |
|------|-----------|------|-----------|
| 무료 | 아이 기질 진단, child-only 리포트, 공유 | 첫 신뢰 형성 | 전체 분석/상담으로 확장 |
| 체험 | 전체 분석, AI 상담, 실천 기록 흐름 경험 | 구독 가치 체험 | 체험 종료 전 구독 |
| 구독 | 상담, 실천 전체 이력, 다음 상담 맥락 누적 | 반복 사용과 유지 | 월 12,000원 |

무료 영역의 역할:

- 사용자가 `이 서비스가 우리 아이를 꽤 잘 이해한다`고 느끼게 한다.
- 하지만 `이제 무엇을 해야 하지?`가 남아야 한다.
- 리포트 마지막 행동은 공유가 아니라 `양육자 분석`, `상담`, `실천 루프`로 이어져야 한다.

구독 영역의 역할:

- 단순 무제한 이용권이 아니다.
- `기록이 쌓일수록 다음 상담이 더 정확해진다`는 지속관리 약속을 판다.
- 가격 페이지도 기능표보다 `리포트 → 상담 → 실천 → 다음 상담` 그림을 먼저 보여준다.

### 3-2. 보류안: 단품 유료 리포트

단품 리포트는 다음 조건을 만족할 때만 실험한다.

- 무료 리포트 열람은 높은데 구독 전환이 낮다.
- 사용자가 `구독은 부담스럽지만 전체 리포트는 사고 싶다`는 신호를 반복적으로 보인다.
- 스토어/IAP와 웹 PG에서 단품 구매·환불·복원 플로우를 감당할 준비가 되어 있다.

실험 상품 예시:

| 상품 | 가격 가설 | 제공 범위 | 주의점 |
|------|-----------|-----------|--------|
| 전체 리포트 패스 | ₩4,900~₩9,900 | 아이+양육자+관계 리포트 1회 | 구독 가치와 충돌 가능 |
| 상담 1회 체험권 | ₩3,900~₩5,900 | 특정 고민 상담 1회 | 반복 루프 약화 가능 |
| 첫 달 할인 구독 | ₩8,400 첫 달 | 전체 프리미엄 1개월 | 현재 구조와 가장 잘 맞음 |

권장 순서:

1. 구독 중심 전환 페이지를 먼저 개선한다.
2. 2~4주 기준선 데이터를 본다.
3. `가격 부담`이 주요 이탈 사유로 확인되면 단품 리포트 실험을 만든다.

## 4. 신뢰 체계 설계

신뢰는 한 문구로 해결되지 않는다. `분석 근거`, `AI의 역할`, `한계`, `개인정보`, `환불 가능성`이 일관되게 설명되어야 한다.

### 4-1. 신뢰 메시지 계층

| 계층 | 사용자가 궁금해하는 것 | 화면/문서 |
|------|------------------------|-----------|
| 분석 근거 | 이 검사가 뭘 기준으로 하나? | 랜딩, 리포트, 근거 페이지 |
| 개인화 근거 | 왜 우리 아이에게 맞다고 하나? | 리포트 카드, 상담 입력 전 |
| AI의 역할 | AI가 진단하는 건가? | 상담 전 안내, 면책 문구 |
| 한계 | 의학적/심리학적 진단인가? | 리포트 하단, 법적 페이지 |
| 개인정보 | 아이 데이터는 안전한가? | 가입/접수/개인정보 페이지 |
| 결제 신뢰 | 해지/환불은 쉬운가? | 가격 페이지, 구독 관리, 환불 정책 |

### 4-2. 리포트 내 근거 표시

리포트 각 해석 카드에는 긴 논문 설명이 아니라 `왜 이 해석이 나왔는지`를 짧게 보여준다.

예시 구조:

```text
아이의 신호
민준이는 새로운 자극에 빠르게 반응하는 편이에요.

왜 이렇게 봤나요?
자극추구 문항에서 활동/탐색 관련 응답이 높게 나타났고,
위험회피 문항은 상대적으로 낮게 나타났기 때문이에요.

오늘 써볼 말
"궁금한 건 알겠어. 먼저 여기까지 해보고 다음 걸 같이 보자."
```

구현 원칙:

- 점수 그래프보다 `생활 장면 해석`을 먼저 보여준다.
- `문항 응답 → 기질 차원 → 생활 해석 → 오늘의 행동` 순서로 연결한다.
- `진단`, `치료`, `장애`, `정상/비정상` 같은 표현은 피한다.

### 4-3. 전문가 검토 문구 원칙

전문가 검토가 실제로 없으면 `전문가 검토 완료`라고 쓰지 않는다.

허용 문구:

- `기질 이론과 표준화된 설문 구조를 참고해 만든 양육 참고 자료입니다.`
- `의학적·심리학적 진단을 대체하지 않습니다.`
- `발달, 건강, 안전과 관련된 우려는 전문기관 상담을 권장합니다.`

실제 전문가 검토 계약 후에만 가능한 문구:

- `아동상담/심리 전문가가 콘텐츠 구조를 검토했습니다.`
- `검토 범위: 문항 해석 구조, 면책 표현, 상담 안내 문구`

전문가 검토를 도입할 경우 검토 범위를 문서화한다.

- 검토자 자격
- 검토 일자
- 검토 범위
- 검토하지 않은 범위
- 서비스가 진단이 아님을 명시

## 5. 구매 전환 페이지 설계

가격 페이지의 목적은 가격표를 보여주는 것이 아니라 `지금 결제하면 무엇이 달라지는지`를 납득시키는 것이다.

### 5-1. 첫 화면 구성

첫 화면 우선순위:

1. 헤드라인: `리포트에서 끝내지 않고, 오늘 상황까지 이어서 봅니다`
2. 샘플 결과: `아이 속마음 통역 + 오늘의 한마디 + 실천 1개`
3. 가격/CTA: `월 12,000원으로 계속 관리하기`
4. 신뢰 보조: `언제든 해지 가능`, `진단 아님`, `환불 정책 보기`

피해야 할 구성:

- 기능 목록을 첫 화면에 길게 나열
- `무제한 상담`을 가장 큰 가치로 강조
- 리포트 이미지 없이 말로만 설명
- 해지/환불 링크를 숨김

### 5-2. 가격 페이지 섹션

| 순서 | 섹션 | 목적 | 핵심 UI |
|------|------|------|---------|
| 1 | 오늘 바로 얻는 것 | 즉시 효용 제시 | 샘플 처방 카드 |
| 2 | 지속관리 루프 | 구독 이유 설명 | 리포트→상담→실천→다음 상담 흐름 |
| 3 | 우리 아이 맥락 누적 | 대체재와 차별 | 기록이 다음 상담에 반영되는 예시 |
| 4 | 가격 | 결제 행동 | 월 가격, 첫 달 혜택, CTA |
| 5 | 신뢰/한계 | 불안 해소 | 근거, 개인정보, 면책 |
| 6 | 해지/환불 | 방어 | 쉬운 해지, 환불 조건 |

### 5-3. 샘플 결과 카드

구매 전환에서 보여줄 샘플은 점수표가 아니라 `바로 쓸 수 있는 결과물`이어야 한다.

샘플 카드 3종:

1. `아이 속마음 통역`
   - 아이의 행동을 1인칭으로 풀어준다.
2. `오늘의 한마디`
   - 실제 부모가 말할 수 있는 문장.
3. `실천 처방`
   - 기간, 상황, 해볼 행동, 실패 시 대안.

샘플 문구 예시:

```text
아이 속마음 통역
"내가 일부러 안 듣는 게 아니라, 갑자기 멈추라는 말이 내 몸에는 너무 빠르게 느껴져."

오늘의 한마디
"멈추기 어렵지. 그럼 딱 한 번만 더 하고, 다음은 엄마랑 같이 고르자."

실천 처방
전환 3분 전에 선택지를 2개만 줍니다.
예: "파란 컵으로 마실래, 노란 컵으로 마실래?"
```

### 5-4. 가격 페이지 카피 원칙

좋은 문구:

- `지난 실천 기록을 다음 상담이 이어받습니다.`
- `아이의 기질과 오늘 상황을 함께 보고 다음 행동을 정합니다.`
- `결과지를 보는 데서 끝나지 않고, 실제 양육 장면까지 연결합니다.`

약한 문구:

- `AI 상담 무제한`
- `프리미엄 기능 전부 해제`
- `최고의 육아 솔루션`

## 6. 전환 이벤트 설계

현재 문서의 핵심 퍼널은 유지하되, 신뢰/전환 페이지 실험을 보려면 아래 이벤트를 추가한다.

| 이벤트 | 목적 | 주요 파라미터 |
|--------|------|---------------|
| `trust_section_viewed` | 근거/한계 설명 열람 확인 | `section`, `source` |
| `sample_report_viewed` | 샘플 결과 카드 노출 확인 | `sample_type`, `source` |
| `pricing_objection_opened` | 불안 요소 확인 | `objection_type` |
| `refund_policy_clicked` | 환불 정책 관심 확인 | `source` |
| `support_started` | 결제 전/후 문의 확인 | `source`, `topic` |
| `subscription_cancel_intent` | 해지 의도 확인 | `source`, `reason` |

권장 퍼널:

```text
report_viewed
→ report_primary_cta_clicked
→ pricing_viewed
→ sample_report_viewed
→ payment_started
→ payment_completed
```

신뢰 보조 퍼널:

```text
pricing_viewed
→ trust_section_viewed
→ refund_policy_clicked
→ payment_started
```

해석 원칙:

- `refund_policy_clicked`가 높다고 나쁜 것은 아니다. 결제 전 불안을 해소하면 전환에 기여할 수 있다.
- `sample_report_viewed`가 높고 결제 시작이 낮으면 샘플은 흥미롭지만 가격/상품 경계가 약한 것이다.
- `trust_section_viewed` 후 전환이 높으면 신뢰 설명을 더 상단으로 올린다.

## 7. 광고/콘텐츠 유입 실험 설계

광고는 전환 페이지와 이벤트 수집이 준비된 뒤 확장한다. 그 전에는 네이버 블로그/검색형 콘텐츠로 메시지를 검증한다.

### 7-1. 메시지 가설

| 가설 | 메시지 | 주요 채널 | 성공 신호 |
|------|--------|-----------|-----------|
| H1 | `우리 아이 왜 이렇게 예민할까?` | 네이버 블로그, 검색 광고 | 긴 체류, 설문 시작 |
| H2 | `3분 무료 기질 리포트` | 인스타, 맘카페 | 설문 완료 |
| H3 | `오늘 바로 쓰는 한마디` | 인스타 릴스, 카드뉴스 | 리포트→상담 CTA |
| H4 | `형제자매 양육법이 달라야 하는 이유` | 블로그, 커뮤니티 | 공유, 저장 |
| H5 | `상담은 부담스럽지만 지금 도움이 필요할 때` | 검색 광고 | 가격/상담 진입 |

### 7-2. 콘텐츠 구조

네이버 블로그 글 템플릿:

```text
제목: 아이가 전환을 어려워하는 이유: 기질로 보는 3가지 신호
1. 부모가 흔히 겪는 장면
2. 기질 관점에서 보는 이유
3. 오늘 써볼 말 3개
4. 무료 아이 기질 리포트 CTA
5. 진단이 아닌 양육 참고 자료라는 안내
```

인스타 카드뉴스 템플릿:

```text
1장: "왜 우리 아이는 멈추라는 말을 이렇게 싫어할까?"
2장: 전환 어려움은 고집만이 아닐 수 있음
3장: 자극추구/위험회피 관점의 간단 설명
4장: 오늘 써볼 말
5장: 3분 무료 리포트 CTA
```

맘카페/커뮤니티 원칙:

- 직접 판매글보다 `상황별 도움 글` 중심.
- 댓글에서 진단처럼 답하지 않는다.
- 체험 후기/리포트 예시는 개인정보와 아동 식별 정보를 제거한다.

## 8. 환불·해지·CS·리뷰 플로우

스토어 결제는 플랫폼 정책과 사용자 기대가 강하게 작동한다. Apple과 Google 모두 구독 관리/환불 처리가 플랫폼 흐름과 연결되므로 앱 안에서는 `어디서 관리하는지`를 명확히 안내해야 한다.

참고 공식 문서:

- Apple Auto-renewable Subscriptions: https://developer.apple.com/app-store/subscriptions/
- Apple Handling Subscriptions Billing: https://developer.apple.com/documentation/StoreKit/handling-subscriptions-billing
- Google Play Billing manage purchases: https://developer.android.com/google/play/billing/manage-purchases
- Google Play refunds for developers: https://support.google.com/googleplay/android-developer/answer/2741495
- Firebase DebugView: https://firebase.google.com/docs/analytics/debugview

### 8-1. 구독 관리 UX

구독 관리 화면은 raw status를 보여주지 않는다.

| 내부 상태 | 사용자 문구 | CTA |
|-----------|-------------|-----|
| `ACTIVE` | 다음 결제일까지 이용 가능 | 구독 관리 |
| `ACTIVE + cancelled_at` | 해지 예약됨, 기간 종료일까지 이용 가능 | 구독 계속하기 |
| `PAST_DUE` | 결제 확인이 필요합니다 | 결제수단 확인 |
| `EXPIRED` | 프리미엄이 만료되었습니다 | 다시 시작하기 |

앱스토어/플레이스토어 결제 사용자는 앱 내부에서 직접 해지한 것처럼 보이게 하지 않는다.

```text
이 구독은 App Store/Google Play에서 관리됩니다.
해지와 결제수단 변경은 스토어 구독 관리 화면에서 진행해 주세요.
```

### 8-2. 환불 정책 UX

환불 정책은 법률 문서에만 두지 않고 가격 페이지와 구독 관리 화면에서 접근 가능해야 한다.

사용자에게 보여줄 요약:

```text
결제 후 7일 이내이고 유료 상담/실천 기록 전체 열람을 사용하지 않았다면 전액 환불을 요청할 수 있어요.
이미 유료 기능을 사용한 경우에는 남은 기간 기준으로 부분 환불을 검토합니다.
앱스토어/플레이스토어 결제는 각 스토어 정책과 절차가 함께 적용됩니다.
```

CS 처리 상태:

| 상태 | 설명 | 사용자 응답 |
|------|------|-------------|
| 접수 | 문의 도착 | 자동 접수 안내 |
| 확인 중 | 결제/사용 이력 확인 | 예상 처리 시간 안내 |
| 처리 가능 | 환불/해지 가능 | 다음 단계와 예상 완료일 |
| 스토어 처리 필요 | Apple/Google 절차 필요 | 스토어 이동 경로 안내 |
| 완료 | 처리 완료 | 결과와 재문의 경로 |

### 8-3. CS 응답 SLA

권장 SLA:

- 결제/환불 문의: 영업일 1일 이내 1차 답변
- 앱 접속/결제 실패: 당일 우선 확인
- 리포트 품질/불쾌 표현 신고: 24시간 이내 확인
- 아동 안전/위기 표현 포함 문의: 즉시 전문기관 안내 문구 포함

CS 분류:

| 분류 | 예시 | 우선순위 |
|------|------|----------|
| 결제 실패 | 결제됐는데 구독 안 보임 | P0 |
| 환불 | 실수 결제, 기대 불일치 | P0 |
| 해지 | 어디서 해지하는지 모름 | P0 |
| 리포트 품질 | 우리 아이와 맞지 않음 | P1 |
| 상담 결과 불만 | 답변이 일반적임 | P1 |
| 계정/로그인 | 소셜 로그인 문제 | P1 |
| 기능 문의 | 알림, 공유, 기록 | P2 |

### 8-4. 앱스토어 리뷰 대응

나쁜 리뷰 대응 원칙:

- 방어하지 않는다.
- 아이/가정 상황을 추측하지 않는다.
- 결제/환불은 공개 댓글에서 개인정보를 요구하지 않는다.
- 해결 경로를 짧게 제시한다.

템플릿:

```text
불편을 드려 죄송합니다. 결제/구독 상태는 계정과 스토어 상태를 함께 확인해야 해서 공개 댓글로 처리하기 어렵습니다.
앱 내 고객센터 또는 devhohouse@gmail.com 으로 주문 정보와 함께 문의해 주시면 우선 확인하겠습니다.
```

리포트 품질 불만 템플릿:

```text
소중한 의견 감사합니다. 기질아이는 진단이 아니라 양육 참고 자료로 제공되며, 실제 생활 맥락과 다르게 느껴질 수 있습니다.
더 맞는 해석을 제공할 수 있도록 어떤 장면에서 맞지 않았는지 알려주시면 개선에 반영하겠습니다.
```

## 10. 구현 태스크 초안

### Slice A. 가격 페이지 전환력 개선

- `pricing` 첫 화면에 샘플 처방 카드 추가
- 구독 가치 설명을 기능표보다 위로 이동
- 환불/해지/진단 아님 링크를 CTA 근처에 배치
- 이벤트: `sample_report_viewed`, `refund_policy_clicked`

완료 조건:

- 모바일 첫 화면에서 샘플 결과와 결제 CTA가 함께 보인다.
- `pricing_viewed → payment_started` 측정 가능.

### Slice B. 신뢰 근거 체계

- 리포트 카드에 `왜 이렇게 봤나요?` 설명 추가
- `/legal/about` 또는 별도 근거 섹션에 분석 한계와 참고 구조 정리
- 전문가 검토 문구를 실제 검토 상태에 따라 분기

완료 조건:

- 사용자가 리포트 해석 근거와 한계를 1분 안에 이해할 수 있다.
- 의학적 진단으로 오해할 표현이 없다.

### Slice C. CS/환불 방어

- 구독 관리 화면에서 결제 출처별 관리 위치 명시
- 환불 정책 요약을 가격/구독 관리 화면에 노출
- CS 템플릿과 상태표를 운영 문서화

완료 조건:

- 사용자가 해지/환불 경로를 앱 안에서 찾을 수 있다.
- 운영자가 문의 유형별 답변 기준을 갖는다.

### Slice D. 콘텐츠 유입 실험

- UTM 규칙 정의
- 콘텐츠 메시지 4종 제작
- 채널별 전환 리포트 주간 기록

완료 조건:

- 메시지별 `survey_flow_completed`, `report_viewed`, `pricing_viewed` 비교 가능.
- 광고 집행 전 어떤 메시지가 결제 의도에 가까운지 알 수 있다.
