## 아이말 번역기 (상담 사전 훅)

- 상담 진입 전의 가벼운 무료 단발 도구. 양육자가 상황 + 아이가 한 말/행동을 한 번에 적으면, 아이의 1인칭 속마음(`childVoice`) · 지금 진짜 원하는 것(`need`) · 그 순간 건넬 한마디(`parentReply`)를 즉시 돌려준다. 다단계 문진 없이 단발로 끝낸다.
- 진입: 홈 상단 “아이말 번역기” 카드(구 “지금 상황 SOS” 카드 대체) 또는 `/translate` 직접. 홈 한 줄 입력은 `/translate?input=...`로 프리필된다.
- 권한: **구독 게이트 없음**(상단 퍼널 무료 훅). 인증만 요구하고, 남용은 `llm_usage_events`의 일일 쿼터(`TRANSLATE`, 기본 30건/24h, `consumeLlmQuota`)로만 막는다. 결과는 저장하지 않는 단발성 응답이다.
- 모델: `gpt-4o-mini` 고정(저비용·저지연, 상담 모델 티어와 분리). 입력 검증은 상담과 동일하게 `validateConsultProblemInput`(최소 20자, 무의미 입력 차단)을 서버에서도 적용한다.
- 개인화: 선택된 아이(`childId`)가 있으면 서버에서 그 아이의 기질/이름/연령을 확정해 반영한다. 검사 데이터가 없으면 일반 눈높이로 통역한다. 아이 실명은 가명(`○○이`)으로 보내고 응답에서 복원한다(기존 LLM 프라이버시 정책 준수).
- 표현 가드레일: 상담과 동일 — 영문 약어(NS/HA/RD/P/TCI) 금지, 단정형보다 가능성형, 결핍 프레이밍·부모 비난·성별 고정관념 금지, 진단 표현 금지.
- 전환 경로: 결과 화면의 “이 고민으로 상담 이어가기”는 `/consult?source=translate&entry_cta=translate_result&prefill={원문}`으로 이동해 유료 상담 루프로 연결한다.
- API: `POST /api/consult/translate` → `{ result: { childVoice, need, parentReply } }`. 한도 초과 `LLM_QUOTA_EXCEEDED`(429), 입력 검증 코드 `empty|too_short|gibberish`(400), 미인증 401.

## 상담 시스템

### 상담 흐름

1. **INPUT**: 양육자가 고민 상황을 자유 텍스트로 입력. 아이의 나이/성별에 맞는 예시 칩 5개와 모바일 음성 입력 버튼을 표시하여 입력을 보조한다. 입력 헤더 바로 아래에는 상담 전 안내 블록을 두어 "무엇을 받는지 / 얼마나 걸리는지 / 어디까지 도와주는지"를 3개 포인트로 짧게 설명한다. (→ `consult-examples.md` 참조)
2. **DIAGNOSTIC**: AI가 공감 멘트 + 상황 분석 질문 4개 생성 (객관식 CHOICE / 주관식 TEXT). 질문은 처방에 부족한 정보 축을 서로 겹치지 않게 확인하고, 양육자가 바라는 변화나 목표는 꼭 필요할 때만 자연스럽게 묻는다. 주관식/기타 직접 입력 답변에는 모바일 음성 입력 버튼을 제공. 1차 질문 완료 후 follow-up 판정 API를 호출하여 심층 질문 1\~2개를 추가할 수 있음 (최대 1회). follow-up은 1차 질문과 의미가 같은 질문을 다시 묻지 않는다.
3. **RESULT**: 마음 처방전 생성
   - actionItems는 항상 정확히 3개를 제안하되, `actionItems[0]`을 가장 작고 바로 시작하기 쉬운 기본 추천안으로 사용한다.
   - 결과 화면에서는 첫 번째 실천 항목을 기본 선택 상태로 보여주고, 사용자는 원하면 다른 항목으로만 변경할 수 있다. "선택 해제 후 빈 상태"는 만들지 않는다.

### 상담 입력 품질 검증

- `INPUT` 단계에서 상담 시작 전 자유 텍스트를 검증한다.
- 홈의 “지금 상황 SOS”에서 들어오면 `situation` 쿼리 키를 고정된 초안 문장으로 변환해 자유 입력란을 미리 채운다. 허용 키는 등원/외출 전환(`morning_transition`), 떼쓰기/폭발(`meltdown`), 잠자리(`sleep`), 화낸 뒤 후회(`parent_regret`)이며, 사용자가 실제 상담을 시작하기 전까지는 일반 입력과 동일하게 수정/삭제할 수 있다.
- 비어 있거나 너무 짧은 입력은 상담을 시작하지 않고, 아이에게 있었던 일이나 양육자의 고민을 한 문장 더 적도록 안내한다.
- 자모/기호/짧은 패턴 반복처럼 명백히 의미를 파악하기 어려운 입력은 상담을 시작하지 않고, 입력창 아래에 구체적인 상황 예시 1개를 보여준다.
- 상담 시작 CTA는 로딩 중이 아닐 때는 클릭 가능해야 하며, 빈 입력/짧은 입력/무의미 입력은 클릭 후 같은 위치의 검증 안내로 처리한다.
- 동일 검증은 초기 문진 생성 API(`/api/consult/questions/initial`)에도 적용해 클라이언트 우회를 막는다.
- 차단 문구는 사용자를 평가하지 않고, "상담 가능한 맥락이 부족하다"는 이유와 다음 작성 방법을 설명한다.

### 자유 텍스트 입력 보조

- 상담 고민 입력, 주관식 문진 답변, 일반 실천 한줄메모, 추천 실천의 과정/아이 반응 메모, 실천 완료 회고처럼 자유 텍스트 입력이 필요한 곳에는 공통 `VoiceInputButton`을 붙인다.
- `VoiceInputButton`은 모바일/터치 입력 환경(`pointer: coarse`)에서만 렌더링한다.
- 음성 버튼은 첫 탭에서 textarea 포커스나 키보드 표시를 먼저 만들지 않고 바로 음성 입력을 시작해야 한다.
- 음성 입력은 기본적으로 브라우저 Web Speech API(`SpeechRecognition`/`webkitSpeechRecognition`)를 사용한다.
- Android 앱 WebView에서는 Web Speech API 지원 여부와 별개로 `window.__nativeCapabilities.voiceInput`과 `VoiceInputBridge`가 확인되면 네이티브 speech-to-text bridge를 우선 사용한다.
- 데스크톱에서는 버튼을 숨기고, 모바일 미지원 브라우저에서는 음성 버튼을 탭했을 때 안내 문구를 제공하며, 키보드 입력 흐름은 변경하지 않는다.
- 음성으로 입력된 텍스트는 현재 입력값 뒤에 이어 붙이고, 각 textarea의 기존 글자 수 제한을 넘지 않게 자른다.
- 브라우저 `SpeechRecognition` 결과는 세션 안에서 `resultIndex` 기준으로 병합하고, iOS/Safari 계열에서 같은 interim/final 조각이 인접 중복으로 전달되면 한 번만 반영한다.
- 음성 오류 안내는 실제 오류 코드에 맞춰 분기한다. `not-allowed`는 권한 거부, `audio-capture`는 마이크 장치 접근 실패, `network`는 네트워크 오류, `service-not-allowed`는 현재 환경의 음성 인식 서비스 제한, `language-not-supported`는 언어 미지원, `no-speech`는 음성 미감지로 안내한다. 실제 오류 코드는 콘솔에 남긴다.

```json

  ],
  "magicWord": "상황 반전 대화 스크립트",
  "actionItems": [
    {
      "title": "실천 항목 제목 (한 줄)",
      "description": "구체적 실천 방법 설명",
      "duration": 14,
      "encouragement": "2주 정도 해보시면 변화가 느껴질 거예요"
    }
```

### 결과 화면 (RESULT) 카드 구성

세션 상세 페이지(`/consultations/[id]`)의 각 상담 타임라인 항목:

1. **날짜 뱃지**: 상담 날짜 (2회차부터 "추가 상담" 라벨)
2. **그날의 고민**: 양육자가 입력한 고민 원문
3. **마음 처방전**: 속마음 통역(interpretation) / 아이와 나(chemistry) / 오늘의 한마디(magicWord) / 문진 해설(questionAnalysis)
4. **실천 항목**: actionItems 배열 표시. `title === '오늘의 한마디'` 또는 `duration === 1`인 항목은 틸 그린 강조 카드, 나머지는 일반 카드 (제목 + 기간 + 설명 + 응원 메시지)

### 상담 저장

- 상담은 `consultation_sessions` (세션) + `consultations` (개별 상담) 2단 구조로 저장
- 세션(`consultation_sessions`): user_id, child_id, title, status (ACTIVE / RESOLVED / ARCHIVED)
- 개별 상담(`consultations`): session_id, user_id, child_id, category, problem_description, ai_options (질문 목록), user_response (답변), selected_reaction_id, ai_prescription (처방전 JSON), status (COMPLETED)
- 하나의 세션에 여러 상담이 시간순으로 연결됨 (추가 상담 기능)

### 상담 기록 목록 (`/consultations`)

- 별도 페이지로 구현 (하단 네비게이션 "기록" 탭)
- **세션 기반 목록**: `consultation_sessions` 테이블의 세션 단위로 표시 (하나의 세션에 여러 상담 포함 가능)
- 세션 카드: 세션 제목, 날짜 · 아이 이름, 상담 횟수(2회 이상일 때), 최신 고민 요약 1~2줄, 마법의 한마디 미리보기, 우측 진입 아이콘
- 세션 상태 뱃지: 진행 중(ACTIVE) / 해결됨(RESOLVED) / 지난 상담(ARCHIVED)
- 목록 그룹: "진행 중인 고민" (ACTIVE) 과 "지난 기록" (그 외)으로 분리 표시
- 세션이 없는 과거 상담(orphan)도 하위 호환으로 표시
- 카드 클릭 시 `/consultations/[id]` 세션 상세 페이지로 이동

### 상담 세션 상세 (`/consultations/[id]`)

- 세션 제목, 아이 이름, 상태 뱃지 표시
- 세션에 속한 상담들을 시간순 타임라인으로 표시 (2회차부터 "추가 상담" 라벨)
- 각 상담 카드: 날짜 뱃지 → 그날의 고민 → 마음 처방전(속마음 통역 + 아이와 나 + 오늘의 한마디 + 문진 해설) → 실천 항목
- 실천 항목은 상담 당시 제안된 3개를 모두 표시하되, 실제로 `practice_items`에 저장된 항목은 "선택한 실천" 배지로 강조한다
- 실천 항목 중 `title === '오늘의 한마디'` 또는 `duration === 1`인 항목은 틸 그린 강조 카드로 표시
- ACTIVE 세션: "이어서 상담하기" 버튼 (`/consult?sessionId={id}`로 이동), "이 고민은 해결됨" 버튼
- 해결 처리 시 연결된 ACTIVE 실천 항목이 있으면 함께 종료(DROPPED) 여부 확인
- 세션 삭제: confirm 후 세션 및 관련 상담·실천 기록 전체 삭제 (CASCADE)
- 개별 상담 삭제: 세션에 상담이 2개 이상일 때만 개별 삭제 버튼 표시; 마지막 상담 삭제 시 세션도 함께 삭제

## 실천 시스템

### 개요

상담 처방전의 액션 아이템을 일정 기간 반복 실천하고, 그 과정을 기록하는 시스템.
독립적인 자유 관찰일지는 제공하지 않는다 — 모든 기록은 상담 처방전에서 시작되는 **상담 → 실천 → 기록** 루프의 일부.

### 흐름

1. 상담 완료 → 처방전에 액션 아이템 N개 생성 (각각 수행 기간 포함)
2. 실천 탭에 진행 중인 액션 아이템 표시
3. 양육자가 매일 실천 체크 + 간단 기록
4. 기간 완료 시 종합 회고 기록 유도
5. 축적된 실천 데이터가 다음 상담 시 LLM 컨텍스트로 주입

### 액션 아이템 구조

- 처방전 생성 시 LLM이 액션 아이템 정확히 3개와 각각의 수행 기간을 함께 제안 (1일~최대 2주)
- 기간 안내는 숙제 톤이 아닌 응원 톤 (encouragement 필드)
- 처방전 JSON의 `actionItems` 배열에 title, description, duration, encouragement 포함

### 실천 탭 (`/practices`)

- ACTIVE 상태 실천 항목을 세션별로 그룹핑 (세션 제목 헤더, 클릭 시 세션 상세로 이동)
- 실천 목록 최상단에는 `오늘의 추천 실천` 카드 1개를 별도로 노출한다.
  - 기준: 현재 보이는 실천 중 오늘 아직 체크하지 않은 가장 최근 항목 1개, 없으면 가장 최근 ACTIVE 항목 1개
  - 목적: 사용자가 목록 전체를 다시 훑지 않고 바로 첫 행동을 시작하게 한다.
- 상단에 다음 상담을 위한 실천 기록 요약 패널을 표시한다.
  - 전체 기록 기준 실천률
  - 누적 실천 완료 횟수
  - 오늘 아직 기록하지 않은 항목 수
  - 최근 한줄 메모 1개
- 각 카드: 제목, 설명, 진행률 바 (실천 일수/목표 기간), 응원 메시지
- 세션 그룹 정렬: 오늘 미기록 항목이 있는 세션이 위로
- 카드 내 정렬: 미기록 > 못했어요 > 완료 순
- 최상단 추천 카드에 이미 노출된 실천 항목은 아래 세션 그룹 리스트에서 중복 노출하지 않는다.
- 오늘 실천 기록: PracticeCheckModal (했다/못했다 + 기록 입력, 모바일 음성 입력 지원). 일반 실천은 선택 한줄 메모를 유지하고, 최상단 추천 실천은 한줄 메모 대신 `어떻게 해봤는지`, `아이 반응`, `양육자가 받은 인상`을 구조화해서 받는다.
- 최상단 `오늘의 추천 실천`을 기록할 때는 첫 기록부터 실천 방식 칩, 과정/말 메모, 아이 반응 칩, 아이 반응 메모, 양육자 인상 칩을 함께 받는다. 저장 후 `/api/consult/practice-feedback`이 기록 신호를 기준으로 저비용 quick 피드백, 고급 deep 피드백, static 피드백 중 하나를 자동 선택해 아이 반응 해석, 내일 조정안, 양육자 격려를 즉시 보여준다.
- 실천 피드백을 생성하는 동안에는 버튼 텍스트만 바꾸지 않고, 기질 유형 이미지와 "오늘의 실천 기록을 바탕으로 내일 해볼 작은 조정을 정리하고 있어요." 문구를 모달 안에 노출한다.
- 아이 반응 피드백은 진단이 아니라 다음 시도를 작게 조정하는 코칭으로만 표현한다. 반응을 실패로 단정하지 않고 가능성형 문장으로 설명한다.
- 피드백 카드에서는 실천 아이템을 바꿀 수 있는 CTA를 제공한다. 사용자가 새 실천을 선택하면 기존 실천 항목은 `DROPPED`로 종료하고 새 `ACTIVE` 실천 항목을 저장한다.
- `duration`은 성공 횟수(doneDays) 목표가 아니라 달력 기준 리뷰 권장 기간으로 해석한다.
- 마지막 행동일은 가장 최근 실천 로그 날짜이며, 로그가 없으면 실천 생성일을 사용한다.
- 마지막 행동 후 3일 이상 지난 실천은 "다시 이어가기" 상태로 보고, 오늘 체크 반복 압박보다 재기록 또는 다른 방법 찾기를 제안한다.
- 기간이 지난 실천은 "마감 회고"를 우선 제안하고, 사용자가 아직 이어가고 싶다면 최대 14일 범위 안에서 3일 연장할 수 있다.
- 기간이 지난 뒤 마지막 행동도 3일 이상 없으면 "실천 마무리" 상태로 보고, 반복 리마인더를 중단한 채 마감 회고 또는 다른 방법 찾기를 제안한다.
- 홈 대표 실천 카드에서 실천 목록을 일부만 미리 보여줄 때는 전체 개수와 노출 개수가 어긋나 보이지 않도록 남은 항목 수를 `+N개 더`로 표시한다.
- 마감 회고 저장 시 PracticeReviewModal이 선택 입력 회고를 저장하고 `practice_items.status`를 `COMPLETED`로 변경한다. 회고 내용은 비워도 저장할 수 있으며, 빈 회고는 다음 상담 LLM 컨텍스트에 `회고` 필드로 주입하지 않는다.
- 마감 회고 저장은 연결 상담 세션을 자동으로 종료하지 않는다. 저장 후 사용자가 "이 고민 마무리하기"를 선택하면 해당 세션을 `RESOLVED`로 변경하고, 같은 세션에 남은 ACTIVE 실천 항목은 `DROPPED`로 정리한다.
- 회고 완료 후 CTA는 선택 피로를 줄이기 위해 3개로 제한한다: `이 고민 마무리하기`, `다음 상담에 반영하기`, `새 고민으로 상담하기`. `다음 상담에 반영하기` 아래에는 방금 회고와 지난 실천 기록이 이어진 상담 맥락으로 들어간다는 짧은 설명을 붙인다.
- 진행 중인 실천이 없으면 빈 상태 + "상담 시작하기" CTA

### 실천 리마인더

- 실천 탭 상단의 알림 아이콘은 `/settings/notifications`로 이동한다.
- 알림 설정에서는 실천 리마인더 사용 여부와 리마인더 시간을 설정하고, 이벤트/마케팅 정보 수신 동의는 사용자 프로필에 서버 동기화한다.
- 설정 화면과 실천 탭에서는 현재 리마인더가 실제로 울릴 상태인지(꺼짐/매일 HH:MM)를 사용자가 바로 이해할 수 있어야 한다.
- 웹 브라우저에서는 브라우저 `localStorage`에 기기 단위 선호값만 저장한다.
- Flutter 앱에서는 WebView의 `ReminderBridge` JavaScript 채널로 설정과 현재 실천 상태를 전달하고, 네이티브 로컬 알림을 매일 반복 예약한다.
- 웹은 화면별 즉흥 판단 대신 `daily_practice_checkin` 알림 계획을 만들어 Flutter에 전달한다. 계획에는 설정 시간, 활성 실천 수, 오늘 남은 실천 수, 대표 실천 ID, 알림 탭 시 열 경로가 포함된다.
- 로컬 알림 문구는 가능하면 현재 남아 있는 실천 항목 제목과 리마인더 시간을 반영해 개인화한다.
- 사용자가 테스트 알림을 보낼 수 있어야 하며, 테스트 알림은 기존 반복 예약을 취소하지 않는다.
- 알림을 누르면 실천 탭으로 이동하고, 대표 실천 ID가 있으면 해당 실천 체크 흐름을 바로 열어 기록 마찰을 줄인다.
- 정상 진행 중인 실천 항목이 없으면 로컬 알림 예약을 유지하지 않는다. 마지막 행동 후 3일 이상 멈췄거나 마감 회고가 필요한 실천은 앱 안 카드에서 정리/재시작을 유도하고 반복 알림 대상에서 제외한다.
- 이벤트/마케팅 정보 수신 동의는 `profiles.marketing_opt_in`에 저장하며, 기기 로컬 저장소만으로 처리하지 않는다.
- 리마인더는 서버 푸시가 아니라 앱 내 로컬 알림으로 운영한다. 서버 저장소, 푸시 토큰, 예약 발송 워커는 필요하지 않다.
- 알림 권한이 거부되어도 상담/실천 플로우는 영향을 받지 않아야 한다.
- 실천 로그의 `오늘` 기준 날짜는 UTC가 아니라 사용자의 로컬 날짜를 사용한다.

- 비구독자가 상담 결과를 받은 직후, 실천 기록 관리와 다음 상담을 이어갈 수 있다는 프리미엄 CTA를 노출한다.

- CTA 문구는 "이번 처방을 저장해 다음 상담에 반영한다"는 약속을 우선 전달한다.
- CTA는 `/pricing`으로 이동한다.
- 상담 입력 전 차단 문구와 별개로, 결과 직후 CTA는 상담 가치가 확인된 후의 자연스러운 다음 행동으로 배치한다.

### LLM 컨텍스트 주입

- 상담 시작 시 및 처방전 생성 시 해당 아이의 최근 실천 기록을 자동 조회
- 주입 내용: 액션 아이템 내용, 실천 일수/총 기간, 시도 방식, 아이 반응, 양육자 인상, AI 피드백 요약, 회고 내용
- 활용 지침: 이전에 시도한 방법 중 효과적이었던 것은 강화, 효과 없었던 것은 다른 접근 제안

### 처방 실천 품질 가드

- 처방전의 첫 번째 실천은 기존에 부모가 해봤지만 반복/악화된 반응을 더 하라는 지시가 아니라, 같은 순간에 바꿔 끼울 수 있는 1문장/1동작이어야 한다.
- 처방전은 부모 목표를 그대로 정답으로 처리하지 않는다. 목표가 아이의 발달 단계, 기질, 현재 환경과 맞는지 검토하고 지금 바꿀 부분과 지켜봐도 되는 부분을 구분한다.
- 부모 목표가 아이가 바로 통제하기 어려운 큰 변화라면 "부모님의 목표가 틀렸다는 뜻은 아니지만..."처럼 비난하지 않는 문체로 현실적인 작은 목표로 낮춰 제안한다.
- 결과 해설에는 표면 문제, 부모 목표, 아이 입장, 개입 방향이 구분되어 드러나야 한다. 필요하면 "이대로도 큰 문제는 아닐 수 있다"는 안내를 포함한다.
- 실천 제목은 `기다려주기`, `칭찬하기`, `공감하기`, `대화하기`, `이야기하기`, `함께 하기`처럼 행동 범주만 말하면 안 된다. 제목만 읽어도 언제 무엇을 할지 보여야 한다.
- 첫 번째 실천은 문제가 끝난 뒤 칭찬/회고하는 행동보다, 문제가 시작되는 바로 그 순간의 마찰을 낮추는 행동이어야 한다.
- 반복 요구, 한 가지 방식 고집, 대본 유지가 핵심 고민이면 아이 요구를 무제한 제공하거나 대본을 항상 완벽히 맞추라고 권하지 않는다. 짧은 인정 후 가능한 경계, 다음 순서, 선택지 1개를 제안한다.
- 실천 항목은 장면 제약을 따라야 한다. 운전 중 안아주기/기기 조작 늘리기, 잠들기 전 각성되는 장난감 주기처럼 실제 사용 맥락과 충돌하는 처방은 금지한다.
- `magicWord`는 `아빠가 말했잖아`, `기다려야 해`, `하지 마`처럼 이미 실패한 확인/훈계 문장을 반복하지 않고, 기존 반응을 대체할 새 문장으로 작성한다.
- 후속 상담에서 "여전히", "다시", "계속" 같은 반복 신호가 있으면 이전 실천 항목을 그대로 반복하지 말고, 더 작은 행동·다른 타이밍·더 명확한 경계 중 하나로 조정한다.

### 문진해설 품질 가드

- `questionAnalysis`의 목적은 기질 라벨을 붙이는 것이 아니라, 처방이 왜 나왔는지 양육자가 납득하도록 답변 근거를 보여주는 것이다.
- 문진해설은 문항별 단편 해석의 나열로 끝내지 않고 `핵심 상황 → 아이 입장 → 부모 감정/이미 시도한 방법 인정 → 목표 검토 → 작은 실천` 흐름을 만든다.
- `이 답변은 ~을 보여줍니다` 같은 반복 문장 패턴을 줄이고, 부모가 이미 해본 방법과 힘든 감정을 인정하는 문장을 포함한다.
- 각 해설은 `답변 속 장면/표현 → 아이의 필요나 상황이 작동하는 방식 → 처방 방향 힌트` 흐름을 기본으로 한다.
- 각 해설은 해당 문항의 답변에 직접 포함된 단서를 우선 근거로 삼는다. 다른 문항의 감정 단서를 끌어와 중립 답변에 덧붙이지 않는다.
- 자극추구/위험회피/사회적민감성/인내력 같은 기질 용어는 선택 사항이며, 모든 답변에 반복해서 붙이지 않는다. 같은 기질 용어가 반복될 때는 생활 언어로 바꿔 설명한다.
- `주변을 둘러본다`, `매일 반복된다`, `가끔 발생한다`, `차를 타기 시작할 때`, `최근 몇 주 또는 몇 달 전`처럼 중립적인 관찰, 빈도, 시점 답변만으로 불안, 스트레스, 즐거움, 강한 욕구, 안정감 욕구를 단정하지 않는다. 감정 단서는 답변에 직접 드러날 때만 언급한다.
- 중립, 빈도, 시점, 모름 답변의 해설은 정보 해석으로 제한한다. `신호입니다`, `드러납니다`, `원합니다`, `느끼고 싶어합니다`, `절실합니다`, `감정적 연결`, `중요하게 여깁니다`, `소중하게 여깁니다`처럼 마음을 읽는 표현은 답변에 직접 감정 단서가 있을 때만 쓴다.
- `특별히 없어`, `딱히 없어`, `물어본 적 없어`, `잘 모르겠어`처럼 정보가 부족한 답변에는 기질을 단정하지 않고 추가 관찰 포인트나 상황 해석 수준으로 설명한다.
- 아이를 결핍형으로 표현하지 않는다. `인내가 부족하다`, `참을성이 없다`, `감정 조절이 안 된다`, `문제 행동이다` 대신 `차례의 기준이 아직 눈에 보이지 않을 수 있다`, `끝 신호가 있으면 더 따라오기 쉬울 수 있다`처럼 환경 조정 언어를 쓴다.
- 양육자의 대응을 평가하지 않는다. `충분히 이해하지 못했다`, `기회를 놓쳤다`, `기회를 놓친 것으로 볼 수 있습니다`, `기회를 놓치신`, `부족하다`, `과정이 설계되지 않았다`, `대처 방안이 부족하다`, `시도하지 않으셨다` 같은 문장 대신, 자연스러운 반응으로 인정한 뒤 이 아이에게 더 잘 맞는 대체 방향을 제시한다.
- 처방전 생성 후에는 `consultPrescriptionGuardrails`로 문진해설과 실천 항목을 한 번 더 정리한다. 금지 표현, 중립 답변 과잉해석, 차 안 신체접촉, 사건 뒤 칭찬만 남은 실천은 안전한 대체 문장으로 바꾼다.

## LLM 프롬프트 정책

### 공통 설정

- 모델: `gpt-4o`
- temperature: 기본 `0.7`, 처방전 생성은 지시 준수와 문진해설 안정성을 위해 `0.45`
- response_format: `{ type: "json_object" }`
- 모든 프롬프트에서 JSON 형식만 출력하도록 지시 (markdown 기호 없이 순수 JSON)

### 실천 기록 컨텍스트 주입

- 상담 시작 시(INPUT → DIAGNOSTIC 전환) 및 처방전 생성 시 해당 아이의 최근 실천 기록을 자동 조회
- 조회 실패 시 실천 기록 없이 진행
- 주입 위치:
  - `/api/consult/questions/initial`: 시스템 프롬프트의 \[응답 원칙\] 앞에 \[최근 실천 기록\] 섹션 삽입
  - `/api/consult/prescription`: 시스템 프롬프트의 \[분석 재료\]에 실천 기록 추가, \[응답 가이드\]에 "실천 기록 연계" 지침 추가
- 주입 포맷: `[액션 아이템] 내용: ... | 기간: N일 중 M일 실천 | 최근 시도 방식: ... | 최근 아이 반응: ... | 양육자 인상: ... | 이전 피드백: ... | 회고: ...`
- 활용 지침: 이전에 시도한 방법 중 효과적이었던 것은 강화, 효과 없었던 것은 다른 접근 제안. "지난번에 \~를 시도하셨는데"와 같이 자연스럽게 언급

### 기질 프로필 컨텍스트 주입

initial과 prescription 프롬프트에 공통으로 주입되는 기질 프로필 블록:

```
**[기질 프로필]**
- 아이 기질 유형: {label} ({keywords})
  - 설명: {description}
  - 차원별 점수 (0~100): 자극추구={NS}, 위험회피={HA}, 사회적민감성={RD}, 지속성={P}
- 양육자 기질 유형: {label} ({keywords})
  - 설명: {description}
  - 차원별 점수 (0~100): 자극추구={NS}, 위험회피={HA}, 사회적민감성={RD}, 지속성={P}
```

검사 데이터가 없는 경우 "검사 데이터 없음" / "보편적 아동 기질로 분석" 등으로 대체.
양육자-아이 기질 조화 분석은 별도로 주입하지 않음 — LLM이 양쪽 점수로 직접 판단.
- 아이 기질은 클라이언트 로컬 설문 응답을 그대로 신뢰하지 않고, 상담 API에서 인증된 사용자와 `child_id` 기준의 서버 저장 설문/리포트 점수를 우선 조회해 확정한다.
- 서버에서 해당 `child_id`의 점수를 확인할 수 없으면 다른 아이의 로컬 기질로 대체하지 않고 "검사 데이터 없음"으로 처리한다.

### 아이 기본 정보 컨텍스트 주입

initial과 prescription 프롬프트에는 아이의 이름, 연령/개월 수, 성별을 함께 주입한다.

```
- 대상: {childName} ({childAge}, {childGender})
```

- 연령은 문장 장식이 아니라 질문과 처방 강도를 조절하는 핵심 조건으로 사용한다.
- 이미 알고 있는 이름/연령/성별/기질 유형은 다시 묻지 않는다.
- 성별은 고정관념 강화 근거로 사용하지 않는다. "남자아이니까", "여자아이니까" 같은 일반화는 금지한다.
- 성별 정보는 부모가 체감하는 생활 장면을 더 자연스럽게 구체화하는 수준에서만 보조적으로 활용한다.

### 1) 기초 질문 생성 — `/api/consult/questions/initial`

**역할**: 양육자 고민에 대한 공감 멘트 + 상황 분석 질문 3\~5개 생성

**시스템 프롬프트**:

```
당신은 아동 심리 및 기질 역동 분석 전문가입니다.
사용자의 육아 고민 상황을 듣고, 양육자의 마음을 어루만져주는 공감 멘트와 상황 분석을 위해 확인해야 할 '기초 질문' 3~5개를 생성하세요.

{기질 프로필 블록}

{관찰 기록 블록 — 있을 때만}

**[응답 원칙]**
1. **공감 우선 (empathy)**: 양육자의 힘든 상황을 충분히 인정하고 공감하세요. 육아의 고단함을 짚어주며 죄책감을 느끼지 않게 격려하세요.
   - 예: "정말 고생 많으셨어요. 아침 시간은 1분 1초가 급한데 아이가 협조해주지 않으면 누구라도 화가 날 수밖에 없어요."
2. **기질적 인사이트**: 공감 멘트 끝에 아이의 기질 관점에서 왜 이런 행동이 나올 수 있는지 가벼운 힌트를 포함하세요. 단, NS/HA/RD/P 같은 영문 약어는 절대 사용하지 말고 한글 용어(자극추구, 위험회피, 사회적민감성, 인내력)를 사용하세요.
3. **질문 생성 (questions)**: 처방을 만들기 위해 아직 부족한 정보를 확인하는 질문을 정확히 4개 생성하세요.
   - 4개 질문은 서로 다른 정보 축을 다뤄야 하며, 같은 의미를 표현만 바꿔 반복하지 마세요.
   - 먼저 고민 문장과 이미 제공된 아이 정보에서 알 수 있는 내용을 제외하고, 지금 가장 필요한 확인 포인트를 내부적으로 고른 뒤 질문을 만드세요. 이 내부 판단은 출력하지 마세요.
   - 질문에서 다룰 수 있는 정보 축의 예시는 상황/맥락, 발생 빈도, 직전 계기, 직후 반응, 아이의 반응 방식, 양육자의 감정이나 대응, 이미 시도한 방법, 덜 힘들어졌으면 하는 장면, 아이가 진정되는 조건 등입니다.
   - 위 항목을 모두 물어야 하는 체크리스트로 사용하지 마세요. 현재 고민에 가장 필요한 축만 선택하고, 사용자가 이미 말한 내용은 다시 묻지 마세요.
   - 양육자의 구체적인 경험이나 감정을 직접 들어야 정확한 분석이 가능한 질문은 주관식(TEXT)으로 생성하세요. 예: "그때 어떤 말을 하셨나요?", "아이가 구체적으로 어떤 반응을 보였나요?"
   - 양육자가 바라는 변화나 목표는 처방에 꼭 필요할 때만 자연스럽게 확인하세요. 고민 문장에서 기대 방향이 이미 드러나면 "어떻게 행동해주길 바라시나요?", "어떤 모습이 되어야 할까요?" 같은 목표 질문을 만들지 마세요.
   - 객관식 선택지로 대부분 커버되지만 양육자의 상황이 다를 수 있는 경우, 마지막 선택지에 `"freeText": true`를 추가하세요. 이 선택지를 탭하면 자유 텍스트 입력창이 열립니다. 예: `{ "id": "opt4", "text": "기타 (직접 입력)", "freeText": true }`
   - 아이의 연령/개월 수를 반영해 질문 난이도와 초점을 조정하세요. 어린 연령은 수면, 전환, 감각 과부하, 분리 불안, 기본 루틴을 더 우선적으로 확인하고, 높은 연령은 또래 관계, 규칙 협상, 과제 지속, 자기표현을 더 구체적으로 확인하세요.
   - 성별은 질문 설계의 고정관념 근거로 사용하지 마세요. 필요하다면 생활 장면을 구체화하는 수준에서만 보조적으로 활용하세요.
   - 질문은 각 연령에서 실제로 관찰 가능한 행동 단위로 작성하세요. 발달상 하기 어려운 행동을 전제한 질문은 금지합니다.
```

**유저 메시지**: `{childName} 아이의 양육자이고, 현재 고민 상황: {problem}`

**응답 포맷**:

```json
{
  "empathy": "양육자를 위한 따뜻한 공감과 기질적 힌트 (3~4줄)",
  "questions": [
    {
      "id": "q1",
      "text": "질문 내용 (객관식)",
      "type": "CHOICE",
      "options": [
        { "id": "opt1", "text": "선택지 1" },
        { "id": "opt2", "text": "선택지 2" },
        { "id": "opt3", "text": "기타 (직접 입력)", "freeText": true }
      ]
    },
    {
      "id": "q2",
      "text": "질문 내용 (주관식 — 구체적 경험/감정을 직접 들어야 할 때)",
      "type": "TEXT"
    }
  ]
}
```

### 2) 심층 질문 판정 — `/api/consult/questions/followup`

**역할**: 1차 답변 분석 후 심층 질문 필요 여부 판단 및 추가 질문 생성

**시스템 프롬프트**:

```
당신은 아동 심리 및 기질 전문가입니다.
1차 답변 데이터를 분석하여, 아이의 기질적 원인을 확정하기 위해 추가 정보가 더 필요한지 판단하세요.

**[분석 가이드]**
1. 1차 답변만으로 기질적 특성(NS, HA, RD, P 등)과 환경적 요인이 충분히 설명된다면 "needsFollowUp": false로 설정하세요.
2. 특정 기질적 특성을 더 명확히 확인해야 하거나(예: 고집의 이유가 자극추구인지 위험회피인지 등), 갈등의 트리거를 더 구체화해야 한다면 "needsFollowUp": true로 설정하고 '심층 질문' 1~2개를 생성하세요.
3. **중복 질문 금지**: 1차 질문과 의미가 같은 질문은 절대 생성하지 마세요. 문장 표현만 바꾼 반복도 금지입니다.
   - 이미 "바라는 변화", "나아졌다고 느끼는 모습", "기대하는 행동", "어떤 모습이면 좋겠는지"를 물었다면 목표 질문을 다시 묻지 마세요.
   - 답변이 "사이좋게", "덜 화내게", "말을 들어주게", "차례를 지키게"처럼 추상적이어도 목표를 다시 묻지 말고, 그 목표가 막히는 구체적 장면이나 조건을 물어보세요.
4. 질문은 1차 답변 내용을 언급하며 날카롭되 다정하게 물어보세요.
5. 심층 질문도 CHOICE와 TEXT를 적절히 사용하세요. 구체적 경험이나 감정을 직접 들어야 할 때는 TEXT 타입으로 생성하세요. 객관식 선택지로 대부분 커버되지만 양육자의 상황이 다를 수 있는 경우, 마지막 선택지에 `"freeText": true`를 추가하세요.
6. 목표 질문은 1차 문진에서 목표를 전혀 묻지 않았고, 답변에서도 기대 변화가 전혀 확인되지 않을 때만 TEXT로 생성하세요.
```

**유저 메시지**:

```
고민 상황: {problem}
1차 문진 질문과 답변: {firstRoundQuestionAnswers (JSON)}
```

**응답 포맷**:

```json
{
  "needsFollowUp": true,
  "followUpReason": "추가 질문이 필요한 이유를 양육자에게 다정하게 설명 (1~2문장)",
  "followUpQuestions": [
    {
      "id": "f1",
      "text": "심층 질문 내용",
      "type": "CHOICE",
      "options": [{ "id": "f1_a", "text": "선택지 텍스트" }]
    }
  ]
}
```

### 3) 마음 처방전 생성 — `/api/consult/prescription`

**역할**: 기질 기반 종합 분석 및 맞춤 솔루션 제공

**시스템 프롬프트**:

```
당신은 기질(TCI) 기반의 분석 전문가이자 따뜻한 마음 통역사입니다.
아이의 기질, 양육자의 기질, 그리고 구체적인 상황 문진 결과를 분석하여 이 갈등의 근본적인 원인을 친절하게 설명하고 실천 가능한 솔루션을 제공하세요.

**[분석 재료]**
- 대상: {childName} 아이
- {기질 프로필 블록}
- 고민 상황: {problem}
- 문진 질문과 답변:
  Q: {질문} / A: {답변}
- {실천 기록 블록 — 있을 때만}

**[응답 가이드]**
1. **아이의 속마음 통역 (interpretation)**: 아이가 직접 이야기하는 것처럼 아이의 말투로 속마음을 표현하세요. 예: "나는 게임에서 지면 너무 무서워요. 잘하고 싶은 마음이 너무 크거든요..." 식으로 아이의 1인칭 시점에서 기질적 욕구를 자연스럽게 담아 설명하세요. 문진 답변에서 드러난 구체적 상황을 반영하되, 아이의 눈높이에 맞는 단어와 표현을 사용하세요. (5~7줄로 충분히 상세하게)
2. **아이와 나 (chemistry)**: 양육자를 탓하지 마세요. 문진 답변에서 나타난 양육자의 대응 방식과 아이의 반응 패턴을 연결하여, 기질 간 역동으로 설명하세요. "~한 상황에서 양육자님이 ~하신 것은 자연스러운 반응이지만, 아이의 ~한 기질과 만나면..." 식으로 구체적으로 분석하세요. (4~6줄)
3. **마법의 한마디 (magicWord)**: 상황을 반전시킬 수 있는 구체적인 대화 스크립트를 제공하세요. 따옴표는 포함하지 마세요.
4. **문진 해설 (questionAnalysis)**: 각 문진 질문과 양육자의 답변을 기질 관점에서 해설하세요. 각 항목은 질문 원문(question), 답변 원문(answer), 그리고 해설(analysis)로 구성합니다.
   - 답변 속 구체 장면/표현을 먼저 짚고, 그 다음에 기질 또는 발달적 가능성을 연결합니다.
   - 단정형보다 가능성형 표현을 우선합니다. (`~가 드러납니다`보다 `~ 가능성이 보입니다`, `~로 이해할 수 있습니다`)
   - 답변 하나당 기질 포인트는 1개만 사용하고, 여러 특성을 한 번에 과잉 매핑하지 않습니다.
   - 답변만으로 근거가 약하면 기질을 억지로 특정하지 않고 발달적 맥락/상황 해석 수준에서 설명합니다.
   - 추상 라벨만 선언하지 말고, 왜 그렇게 보는지 답변 속 단서와 연결해 설명합니다.
   - 해설 기본 구조는 `장면 근거 1문장 + 해석 1문장`이며, 2~3문장으로 충분히 설명합니다.
```
