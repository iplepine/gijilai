# 홈 화면 정책

마지막 갱신일: 2026-07-03

## 화면 분기

홈 화면은 사용자 상태에 따라 세 가지로 분기된다.

| 상태 | 조건 | 표시 |
|------|------|------|
| 비로그인 웹 | `user` 없음 + 일반 브라우저 | `LandingPage` 컴포넌트 렌더링 |
| 비로그인 앱 | `user` 없음 + `gijilai_app` WebView | 소개 화면 대신 `/login`으로 이동 |
| 신규 사용자 | 등록된 아이 없음 (DB + 로컬 intake 모두 없음) | 환영 히어로 카드 + 온보딩 모달 |
| 기존 사용자 | 아이 1명 이상 등록 | 아이 프로필 + 기능 카드 리스트 |

## 첫 로딩 화면

- 인증/홈 대시보드 데이터를 확인하는 동안에는 단순 스피너 대신 기질 유형 일러스트, 짧은 로딩 문구, 얇은 진행 표시를 함께 노출한다.
- 아직 선택된 아이의 기질 맥락을 알 수 없는 첫 로딩에서는 기본 아동 기질 이미지(`/child_type/type_lhh.jpg`)를 사용한다.
- 이미지는 `next/image`로 고정 비율 안에 렌더링해 로딩 화면에서 레이아웃이 흔들리지 않게 한다.
- 첫 로그인 직후 아이콘 폰트가 늦게 붙더라도 `child_care`, `arrow_forward` 같은 Material icon ligature 문자열이 사용자에게 노출되지 않아야 한다.

## 신규 사용자 레이아웃

1. **환영 히어로 카드** — 양육자 이름 포함 인사, 아이 프로필 등록 CTA (`/settings/child/new`)
2. **온보딩 모달** — 첫 방문 시 자동 표시. 모바일 WebView에서 화면보다 과하게 길어지지 않도록 컴팩트 간격과 최대 높이를 적용하며, "아이 정보 등록하기" 또는 "나중에 둘러볼게요" 선택 가능.

## 기존 사용자 레이아웃

- 홈 콘텐츠는 사용자가 앱을 열었을 때 빠르게 훑을 수 있어야 하므로 스크롤 진입 reveal 애니메이션을 사용하지 않는다. 짧은 콘텐츠를 애니메이션으로 늦게 보여주지 않는다.
- 아이 기질 리포트가 있는 사용자는 “아이말 번역기” 진입점을 항상 볼 수 있다. 이 진입점은 다음 행동 우선순위를 대체하지 않고, 방금 아이가 한 말/행동을 한 줄 적어 `/translate`에서 아이 속마음 번역을 받고 필요하면 상담으로 이어가게 하는 별도 재방문 트리거다. (구 “지금 상황 SOS” 카드를 대체)

### 상단 영역

- **아이 프로필 사진**: 탭하면 이미지 업로드. 사진 없으면 기질 유형 이미지 또는 기본 아이콘 표시.
- **아이 기질 뱃지**: 프로필 사진 아래 뱃지. 검사 완료 시 기질 유형 라벨, 미완료 시 "기질 검사하기" 텍스트. 탭하면 `/report?tab=child` (완료) 또는 `/survey/intro` (미완료).
- **아이 이름 + 나이**: `{이름} ({나이})` 형태. 나이는 36개월 이하면 개월 수, 초과하면 년+개월.
- **아이 선택 드롭다운**: 아이 2명 이상일 때 이름 옆에 `expand_more` 아이콘 표시. 탭하면 드롭다운으로 아이 전환. 선택된 아이는 Zustand `selectedChildId`로 전역 유지.
- **양육자 유형 뱃지**: 양육자 기질은 아이와 무관하게 하나만 표시. 데이터 없으면 "검사 필요" 표시. 양육자 데이터가 있고 아이 검사 미완료 시 탭하면 검사 안내(`/survey/intro`)로 이동, 완료 시 `/report?tab=parent`로 이동.
- **헤더 로고**: "기질아이" 로고 영역은 클릭 가능하며, 현재 위치와 관계없이 홈(`/`)으로 이동한다.

### 구독/체험 상태 뱃지

헤더 "기질아이" 로고 오른쪽 끝에 컴팩트 뱃지로 표시한다.

- 앱 WebView(iOS/Android)에서는 상단 헤더와 하단 탭바가 노치/홈 인디케이터/시스템 제스처 영역과 겹치지 않도록 safe area inset을 반영해야 한다. 웹 CSS `env(safe-area-inset-*)`와 앱 쉘이 주입하는 native inset 값을 함께 사용하되, Android는 WebView 자체가 이미 status bar 아래로 배치되므로 상단 헤더가 native top inset을 다시 중복 반영하지 않게 한다. 하단 탭바는 배경을 화면 하단까지 확장하되 탭 아이콘, 라벨, 중앙 버튼의 터치 영역은 native bottom inset 위에 배치한다.

| 사용자 상태 | 뱃지 표시 | 탭 시 이동 |
|------------|----------|-----------|
| 체험 기간 중 | 체험중 D-{남은일수} | `/pricing` |
| 체험 만료 (비구독) | 프리미엄 시작하기 | `/pricing` |
| 구독자 (ACTIVE) | 구독중 | `/settings/subscription` |
| 구독자 (CANCELLED) | 구독중 ~MM/DD | `/settings/subscription` |

### 체험 종료 임박 구독 유도

- 체험 기간 중이고 남은 기간이 2일 이하이며 비구독자인 경우, 기능 카드 리스트 상단에 프리미엄 지속 카드 노출
- CTA는 `/pricing`으로 이동
- 목적은 체험 종료 후에도 지금까지의 상담/실천 기록 맥락이 다음 가이드에 계속 반영된다는 점을 알리는 것

### 기능 카드 리스트

홈은 여러 선택지를 같은 강도로 보여주지 않는다. 아래 우선순위에서 가장 중요한 다음 행동 1개를 상단 강조 카드로 먼저 노출하고, 같은 의미의 일반 카드는 아래 리스트에서 중복 노출하지 않는다.

아이말 번역기 카드는 아이 기질 리포트가 있을 때 기능 카드 리스트 상단에 컴팩트 카드로 노출한다. 한 줄 입력에 상황/아이 말을 적고 보내면 `/translate?input={자유텍스트}`로 이동해 번역 화면을 채운다(빈 입력이면 `/translate`로만 이동). 홈 입력값은 최대 500자로 잘라 URL 쿼리로만 넘기고 별도 저장하지 않으며, 분석 이벤트(`home_translate_clicked`)에는 입력 내용이 아니라 입력 여부/길이만 담는다.

우선순위:

1. 아동 검사 미완료
2. 양육자 검사 미완료
3. 실천 다음 행동 (오늘 미체크 실천, 마무리할 실천, 다시 이어갈 실천)
4. 상담 시작/추가 상담
5. 체험 종료 임박 구독 유도

나머지 카드는 아래 순서대로 배치하며, 조건에 따라 표시/숨김 처리한다.

| 순서 | 카드 | 표시 조건 | 비고 |
|------|------|-----------|------|
| 1 | {아이이름}의 기질 검사 | 선택된 아이의 아동 검사 미완료 | "첫 번째 단계" 뱃지, 빠른 결과 보기 CTA → `/survey/intro` |
| 2 | 나의 양육 성향 검사 | 양육자 검사 미완료 AND 아동 검사 완료 | "필수 진행 단계" 뱃지, 이어하기/시작하기 CTA → `/survey?type=PARENT` |
| 3 | 오늘의 마법의 한마디 | 실천 중인 상담에 magicWord 존재 | 캐러셀(5초 자동 롤링, 스와이프 지원), 선택된 아이로 필터링 |
| 4 | 오늘의 실천 / 마무리할 실천 | 오늘 미체크 실천 또는 마무리할 실천 있음 | 정상 진행 중인 오늘 미기록 실천은 홈에서 `했어요`/`못했어요`/`나중에`를 바로 선택할 수 있게 하고, 자세한 기록이나 마무리/재시작이 필요한 상태는 `/practices?focusPracticeId=...`로 연결 |
| 5 | 상담 유도 | 아동 검사 완료 AND (상담 이력 없음 OR 진행 중 실천 없음) | "육아 고민, 기질로 풀어볼까요?" → `/consult` |
| 6 | 기질 분석 리포트 | 아동 검사 완료 | 컴팩트 카드, "결과 보기" → `/report` |

홈의 상담 유도 카드는 자유 텍스트를 미리 받거나 검증하지 않는다. 상담 입력 품질 검증과 실패 사유 안내는 `/consult` 입력 화면에서 처리한다.

### 실천 다음행동 인라인 처리

- 상단 강조 카드가 `오늘 미체크 실천`이고 해당 실천의 생애주기 상태가 `ACTIVE`인 경우, 홈에서 바로 `했어요`, `못했어요`, `나중에`를 선택할 수 있다.
- `했어요`와 `못했어요`는 오늘 날짜의 `practice_logs`를 즉시 upsert한다. `못했어요`도 실패가 아니라 다음 상담 조정을 위한 기록으로 취급한다. 홈 인라인 저장은 사용자가 추가 입력을 하지 않았다는 전제에서 기본 구조화 신호를 함께 저장하고, 체험/구독 접근 권한이 있으면 `/api/consult/practice-feedback`을 호출해 짧은 내일 조정안을 메시지로 갱신한다.
- `나중에`는 서버 기록을 남기지 않고 현재 홈 세션에서만 해당 항목을 잠시 숨긴다. 사용자는 실천 탭에서 언제든 다시 기록할 수 있다.
- 자세한 메모, 아이 반응, AI 피드백, 실천 변경, 회고가 필요한 경우에는 `focusPracticeId`를 붙여 `/practices`의 기존 상세 플로우로 연결한다.
- `DUE_FOR_REVIEW`, `STALE`, `NEEDS_RECONNECT` 상태는 판단과 설명이 필요하므로 홈에서 즉시 완료하지 않고 기존 실천/회고 화면으로 보낸다.
- 홈 대표 실천 카드가 실천 목록을 최대 2개까지만 미리 보여줄 때는 전체 개수와 사용자가 보는 개수가 어긋나지 않도록 남은 항목 수를 `+N개 더`로 표시한다.

> **참고**: 재검사 쿨다운 상태는 내부적으로 추적하고 있으나(`cooldownStatus`), 현재 홈 화면에 재검사 카드 UI는 렌더링하지 않는다.

### 빠른 첫 결과 진입

- 설문 안내 화면(`/survey/intro`)은 두 가지 진입을 제공한다.
- `빠르게 아이 결과 먼저 보기`는 아이 기질 설문만 먼저 완료하고 `/report?child_only=true`로 이동한다.
- `처음부터 전체 분석 시작하기`는 아이 설문 뒤 곧바로 양육자 기질과 양육 스타일 설문까지 연속 진행한다.
- 홈의 첫 번째 검사 카드는 빠른 첫 결과 경로를 더 강하게 강조하되, 최종 선택은 설문 안내 화면에서 하게 한다.
