# 리포트 제품 스펙

## 목적

리포트는 사용자가 "우리 아이를 꽤 잘 이해한다"고 느끼게 만드는 첫 신뢰 지점이다. 목표는 검사 결과 열람이 아니라 상담과 실천으로 이어지는 다음 행동을 만드는 것이다.

## 구성

| 탭 | 역할 |
|----|------|
| 아이 기질 | 아이 기질 유형, 4대 기질 점수, 속마음, 강점, 양육 팁, 마법의 한마디 |
| 양육자 분석 | 양육자 기질, 빛나는 순간, 취약 상황, 자기 돌봄 솔루션 |
| 기질 맞춤 양육 | 아이-양육자 기질 차이, 관계 해석, DO/DON'T, 상황별 대처 |

## 빠른 아이 리포트

- `child_only` 모드는 양육자 기질 데이터가 없는 사용자에게 아이 기질 리포트만 먼저 보여준다.
- 탭 전환은 숨기고, 하단 CTA로 양육자 설문을 안내한다.
- 양육자 기질 데이터가 이미 있으면 `child_only`를 유지하지 않고 전체 리포트의 아이 기질 탭(`/report?tab=child`)으로 정규화한다.
- 목적은 첫 효용 시간을 줄이는 것이다.

## 콘텐츠 원칙

- 영문 약어는 사용자에게 노출하지 않고 한글 차원명만 사용한다.
- 점수 그래프보다 생활 장면 해석과 실전 대사를 먼저 이해시키는 구조를 우선한다.
- `진단`, `치료`, `정상/비정상`처럼 의료적 오해를 부를 표현은 피한다.
- 각 해석은 `응답 → 기질 차원 → 생활 해석 → 오늘의 행동`으로 연결한다.

## 전환 원칙

- 비구독자 리포트 하단은 공유보다 상담/실천/구독 루프를 우선 설명한다.
- CTA는 "리포트에서 끝내지 않고 오늘 상황까지 이어서 본다"는 가치로 작성한다.
- 측정 이벤트는 `report_viewed`, `report_primary_cta_clicked`, `survey_module_started`, `survey_flow_completed`를 기준으로 한다.

## 상세 정책

세부 데이터 키와 탭별 렌더링 규칙은 `../product/policies/report.md`를 기준으로 한다.
