## 적용 절차

가드가 있으므로 **011부터 024까지 순서대로 전부 실행**하는 것이 가장 안전하다
(이미 적용된 016~019 부분은 가드가 스킵한다):

```
011 → 012 → 013 → 014 → 015 → 016 → 017 → 018 → 019 → 020 → 021 → 022 → 023 → 024
```

배포 순서 주의 (022):
1. **마이그레이션 022를 먼저 적용** (컬럼 추가는 기존 코드에 무해)
2. 그 다음 웹 배포 — 공유 API가 share_token 조회로 바뀌었으므로, 코드를 먼저 배포하면 적용 전까지 공유 기능이 깨진다

023/024는 코드가 마이그레이션 없이도 안전하게 동작한다
(023 미적용 → LLM 쿼터 fail-open, 024 미적용 → 기존 동작 유지).

## 적용 후 검증 쿼리

```sql
-- 011/013: usage events 테이블 + 확장된 event_name 제약
select count(*) from public.subscription_usage_events;

-- 012: marketing_opt_in
select column_name from information_schema.columns
  where table_name = 'profiles' and column_name = 'marketing_opt_in';

-- 013/014: 실천 피드백 컬럼
select column_name from information_schema.columns
  where table_name = 'practice_logs' and column_name like 'ai_feedback%';

-- 015: child_profile_slots
select count(*) from public.child_profile_slots;

-- 020: self-parent RLS 정책
select polname from pg_policies where tablename = 'consultation_sessions';

-- 022: share_token
select indexname from pg_indexes where indexname = 'idx_reports_share_token';

-- 023: llm_usage_events + check 제약에 SELF_PARENT_* 포함
select count(*) from public.llm_usage_events;
select pg_get_constraintdef(oid) from pg_constraint
  where conname = 'subscription_usage_events_event_name_check';

-- 024: 활성 구독 중복 0건 + unique index
select user_id, count(*) from public.subscriptions
  where status in ('ACTIVE', 'PAST_DUE') group by user_id having count(*) > 1; -- 0 rows
select indexname from pg_indexes where indexname = 'idx_subscriptions_one_active_per_user';
```
