# GJ-002 다음 작업 백로그

마지막 갱신일: 2026-05-04
연결 roadmap: `R-001-consult-report-conversion`
우선순위: P0 → P1 → P2 → P3

## 목적
사용자가 요청한 다음 작업 항목을 우선순위 기준으로 정리하고, 이후 스프린트에서 순차 실행할 수 있도록 백로그로 저장한다.

## P0. 상담 품질 핵심

### 10) 상담 목표 행동 수집 및 반영
- [ ] 현재 상담 과정에서 부모의 최종 목표 행동을 묻는 단계가 있는지 확인한다.
- [ ] “표면 문제”와 “부모가 원하는 변화”를 구분해서 수집하도록 설계한다.
- [ ] 상담 중 “결국 아이가 어떻게 행동해주길 바라시나요?” 같은 질문을 추가한다.
- [ ] “가장 바라는 변화는 무엇인가요?” 질문을 추가한다.
- [ ] “이 문제가 나아졌다고 느끼려면 어떤 모습이 되어야 할까요?” 질문을 추가한다.
- [ ] 상담 정리 결과에 부모의 목표 행동을 명시한다.
- [ ] 상담 해설에서 목표 행동을 기준으로 개입 방향을 제안한다.
- [ ] 예시 케이스에서 “TV 줄이기”와 “한자리에 앉아서 식사하기”를 구분해서 처리한다.
- [ ] 목표 행동이 누락된 경우 추가 질문을 하도록 상담 플로우를 조정한다.
- [ ] 상담 결과에 `표면 문제 / 부모 목표 / 아이 입장 / 개입 방향` 구조를 반영한다.

### 11) 부모 목표 검토 상담 원칙 추가
- [ ] 상담 로직에서 부모의 목표를 무조건 정답으로 처리하고 있는지 확인한다.
- [ ] 부모 목표가 아이 발달 단계와 맞는지 검토하는 단계를 추가한다.
- [ ] 부모 목표가 아이 기질과 맞는지 검토하는 단계를 추가한다.
- [ ] 실제로 개입이 필요한 문제인지 판단하는 단계를 추가한다.
- [ ] 지금 꼭 바꿔야 하는 부분과 지켜봐도 되는 부분을 구분한다.
- [ ] 부모의 불안이나 피로 때문에 문제가 크게 느껴지는 상황을 고려한다.
- [ ] 필요한 경우 부모의 기대를 부드럽게 조정하는 문장을 생성한다.
- [ ] “부모님의 목표가 틀렸다는 뜻은 아니지만...”처럼 비난하지 않는 문체를 적용한다.
- [ ] 결과 해설에 `부모님이 바라는 변화 / 아이 입장에서 보이는 이유 / 지금 바꿀 부분과 지켜볼 부분` 구조를 반영한다.
- [ ] 아이에게 적절하지 않은 목표라면 현실적인 작은 목표로 낮춰 제안한다.
- [ ] “이대로도 큰 문제는 아닐 수 있다”는 안내가 필요한 경우 이를 포함한다.

### 9) 상담 해설 품질 개선
- [ ] 현재 상담 해설 생성 로직 또는 프롬프트를 확인한다.
- [ ] 질문별 답변을 단편적으로 해석하는 구조인지 확인한다.
- [ ] 전체 답변을 종합해 핵심 가설을 만드는 단계가 있는지 확인한다.
- [ ] “이 답변은 ~을 보여줍니다” 같은 반복 문장 패턴을 줄인다.
- [ ] 부모 감정에 대한 공감 문장을 추가한다.
- [ ] 부모가 이미 시도한 방법을 인정하는 문장을 추가한다.
- [ ] 아이 입장에서 상황을 재해석하는 문장을 추가한다.
- [ ] 추상적인 조언 대신 바로 해볼 수 있는 행동 제안을 포함한다.
- [ ] 행동 제안은 1~2개 정도로 구체화한다.
- [ ] 해설 구조를 `핵심 상황 → 아이 입장 → 부모 감정 → 목표 → 작은 실천` 흐름으로 개선한다.
- [ ] TV/식사 사례 기준으로 개선된 해설 샘플을 작성한다.
- [ ] 개선 전/후 해설 품질을 비교한다.

## P1. 상담 시작 및 정리 UX

### 7) 상담 시작 입력 최소 글자 수 검증 불일치 수정
- [ ] 상담 시작 입력창의 현재 최소 글자 수 기준을 확인한다.
- [ ] 화면 표시 글자 수와 실제 검증 글자 수 계산 방식이 같은지 확인한다.
- [ ] `trim()` 적용 여부를 확인한다.
- [ ] 공백/줄바꿈 포함 여부를 확인한다.
- [ ] 버튼 활성화 조건을 확인한다.
- [ ] 부족 안내 문구 표시 조건을 확인한다.
- [ ] `minLength`, `MIN_CONTENT_LENGTH`, `validation`, `isValid`, `canSubmit` 같은 값이 중복 정의되어 있는지 확인한다.
- [ ] 최소 글자 수 기준을 하나의 상수로 통일한다.
- [ ] 버튼 활성화 조건과 안내 문구 표시 조건을 동일한 기준으로 맞춘다.
- [ ] 20자 이상 입력 시 부족 안내 문구가 사라지도록 수정한다.
- [ ] 더 자세한 입력을 권장하려면 에러 문구가 아닌 도움말 문구로 변경한다.
- [ ] `21/500` 상태에서 부족 안내가 노출되지 않는지 테스트한다.

### 6) 상담 시작 화면 하단 여백 개선
- [ ] 상담 시작 화면에서 키보드가 올라왔을 때 버튼 하단 여백을 확인한다.
- [ ] “상담 시작하기” 버튼과 키보드 사이의 빈 공간이 과도한지 확인한다.
- [ ] 입력창 아래 영역의 `padding`을 확인한다.
- [ ] 버튼 컨테이너의 `margin` 또는 `padding`을 확인한다.
- [ ] 불필요한 `Spacer`가 있는지 확인한다.
- [ ] `SafeArea`가 중복 적용되어 있는지 확인한다.
- [ ] `100vh`, `dvh`, `svh` 사용 여부를 확인한다.
- [ ] Flutter WebView에서 keyboard resize 처리가 어떻게 동작하는지 확인한다.
- [ ] 모바일 브라우저와 앱 WebView에서 동일하게 재현되는지 비교한다.
- [ ] 키보드가 올라왔을 때 버튼이 자연스럽게 키보드 위에 위치하도록 수정한다.

### 1) 실천 정리 동작 버튼 구조 개선
- [ ] 실천 정리 화면에서 노출되는 버튼 4개의 기능을 확인한다.
- [ ] 각 버튼의 목적과 클릭 이후 동작을 정리한다.
- [ ] 버튼 4개가 모두 필요한지 검토한다.
- [ ] 주요 버튼과 보조 버튼을 구분한다.
- [ ] 버튼명을 더 직관적으로 수정한다.
- [ ] 가능하면 버튼 개수를 줄이거나 단계형 UI로 변경한다.
- [ ] 변경 후 사용자가 다음 행동을 쉽게 이해할 수 있는지 확인한다.

### 2) 상담 정리의 “다음상담에 이용하기” 문구 개선
- [ ] “다음상담에 이용하기” 버튼의 실제 동작을 확인한다.
- [ ] 이전 상담 내용 중 무엇이 다음 상담에 반영되는지 확인한다.
- [ ] 버튼명을 “이어서 상담하기” 또는 “이 상담 내용을 다음 상담에 연결하기”처럼 명확하게 변경한다.
- [ ] 버튼 아래에 짧은 설명 문구를 추가할지 검토한다.
- [ ] 사용자가 새 상담과 이어진 상담의 차이를 이해할 수 있는지 확인한다.

## P2. 음성 입력 안정화

### 3) 음성 입력 마이크 권한 에러 메시지 개선
- [ ] `VoiceInputButton.tsx`에서 `getUserMedia({ audio: true })` 실패 처리 로직을 확인한다.
- [ ] `SpeechRecognition.onerror` 처리 로직을 확인한다.
- [ ] `no-speech` 외 오류를 모두 권한 문제로 처리하고 있는지 확인한다.
- [ ] `event.error` 값을 기준으로 오류 메시지를 분기한다.
- [ ] `not-allowed`는 권한 거부 메시지로 처리한다.
- [ ] `audio-capture`는 마이크 장치 접근 실패 메시지로 처리한다.
- [ ] `network`는 네트워크 오류 메시지로 처리한다.
- [ ] `service-not-allowed`는 현재 환경에서 음성 인식 서비스 사용 불가 메시지로 처리한다.
- [ ] `language-not-supported`는 언어 미지원 메시지로 처리한다.
- [ ] `no-speech`는 음성이 감지되지 않았다는 메시지로 처리한다.
- [ ] 실제 오류 코드를 콘솔 로그에 남긴다.
- [ ] 권한 문제가 아닌 오류를 “마이크 권한 확인”으로 안내하지 않도록 수정한다.

### 4) Flutter WebView 마이크 permission request 처리 개선
- [ ] `main.dart`에서 WebView `onPermissionRequest` 처리 로직을 확인한다.
- [ ] Android에서 `RECORD_AUDIO` 런타임 권한 확인 후 WebView permission을 `grant`하는지 확인한다.
- [ ] iOS에서도 microphone permission request가 처리되는지 확인한다.
- [ ] microphone-only 요청일 때 iOS WebView permission을 `grant`하도록 처리한다.
- [ ] `AndroidManifest.xml`의 마이크 권한 선언을 확인한다.
- [ ] `MainActivity.kt`의 런타임 권한 요청 로직을 확인한다.
- [ ] `Info.plist`의 `NSMicrophoneUsageDescription`을 확인한다.
- [ ] `Info.plist`의 `NSSpeechRecognitionUsageDescription`을 확인한다.
- [ ] Android 앱에서 권한 허용 후 음성 입력이 동작하는지 테스트한다.
- [ ] iOS 앱에서 권한 허용 후 음성 입력이 동작하는지 테스트한다.

### 5) 음성 입력 수정 패치 적용 및 검증
- [ ] `gijilai_voice_permission_fix.patch` 내용을 확인한다.

- [ ] Android에서 마이크 권한 허용 후 음성 입력을 테스트한다.
- [ ] Android에서 마이크 권한 거부 시 올바른 메시지가 뜨는지 테스트한다.
