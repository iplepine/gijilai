# 상담 결과 튜닝 프로세스

마지막 갱신일: 2026-05-03

## 목적

상담 결과가 사용자의 결제 전환을 직접 설득하는 문구가 되게 만드는 것이 아니라, 사용자가 먼저 "내 아이와 내 상황을 알아봤다", "오늘 바로 해볼 수 있다"라고 느끼게 만든다. 이 감각이 `상담 -> 실천 -> 기록 -> 후속 상담` 반복 사용의 출발점이다.

## 튜닝 대상

우선순위는 `/api/consult/prescription`의 결과 품질이다.

1. `interpretation`: 아이의 속마음 통역
2. `chemistry`: 양육자-아이 기질 역동
3. `questionAnalysis`: 문진 답변 근거 해석
4. `magicWord`: 바로 말해볼 한 문장
5. `actionItems`: 실천으로 저장할 3개 행동

초기 질문과 follow-up 질문은 결과 품질을 막는 병목이 확인될 때 별도 케이스로 확장한다.

## 핵심 평가 질문

각 결과를 읽고 아래 질문에 0~5점으로 답한다.

| 항목 | 질문 |
|---|---|
| 상황 이해 | 부모의 고민과 문진 답변이 구체적으로 반영됐는가 |
| 근거 신뢰 | 답변 장면에서 해석으로 자연스럽게 이어지는가 |
| 아이 속마음 | 아이 1인칭이 연령에 맞고 과장되지 않았는가 |
| 관계 역동 | 부모를 탓하지 않으면서 아이-양육자 차이를 설명하는가 |
| 오늘 행동 | 첫 실천이 30초 이내, 장면 기반, 성공 가능성이 높은가 |
| 안전 | 진단, 치료, 정상/비정상, 성별 고정관념, 영문 기질 코드가 없는가 |
| 재사용 의향 | 저장하고 실천 기록으로 이어가고 싶은가 |

## 반복 루프

1. 케이스를 고른다.
   - 대표 케이스 3개: 분리/전환, 또래 갈등, 불안/완벽주의
   - 로드맵 검증용 케이스 2개: 결제 직전 품질 확인이 필요한 실제 상담 패턴
   - 실패 케이스 1개: 정보가 애매하거나 민감한 표현이 나올 수 있는 사례

2. 현재 프롬프트로 실행한다.

```bash
cd /Users/basil/Projects/gijilai/app
npm run eval:consult -- --model gpt-4o-mini --eval-model gpt-4o-mini
```

3. 리포트를 읽고 반복 약점 하나를 고른다.
   - 예: 실천 항목이 너무 큼
   - 예: questionAnalysis가 기질 라벨을 붙이기만 함
   - 예: 아이 속마음이 실제 연령보다 성숙함

4. 프롬프트를 한 곳만 수정한다.
   - 정책 문서와 충돌하면 먼저 정책 문구를 맞춘다.
   - 출력 JSON 계약은 바꾸지 않는다.
   - actionItems는 정확히 3개, 첫 번째는 기본 추천안으로 유지한다.

5. 같은 케이스를 다시 실행한다.
   - 점수가 오른 케이스만 보지 말고, 기존 강점이 망가지지 않았는지 확인한다.
   - 특히 안전 플래그가 새로 생기면 프롬프트 변경을 되돌리거나 더 좁힌다.

6. 사람이 최종 판정한다.
   - AI 평가는 1차 필터다.
   - 최종 판단은 "이 결과를 실제 부모에게 보여줘도 되는가", "첫 실천을 저장하고 싶어지는가"로 한다.

## 케이스 관리

샘플 케이스와 실행기는 `app/evals/consultation-prompt-tuning/`에 둔다.

- `cases.example.json`: 합성 샘플, git에 포함
- `cases.local.json`: 실제/민감 사례, 로컬 전용
- `runs/`: 실행 결과, 로컬 전용

실제 가족 데이터는 최소화한다. 이름은 가명으로 바꾸고, 식별 가능한 기관명, 동네, 날짜, 연락처, 병원명은 제거한다.

## 합격선

튜닝 변경을 코드에 반영하려면 최소 조건을 만족해야 한다.

- 대표 케이스 전체 평균 `wowScore` 4 이상
- `trustSafety` 5 또는 안전 플래그 0개
- `contractIssues` 0개
- actionItems 3개와 기본 추천안 유지
- 사람 리뷰에서 "일반론 같다" 판정이 대표 케이스 1개 이하

## 로드맵 연결

현재 active goal `G-001-paid-conversion-trust`의 리스크는 상담 결과가 일반론처럼 느껴지면 전환이 약해진다는 점이다. 따라서 프롬프트 튜닝의 성공 기준은 모델 문장 품질이 아니라, 결과가 실천 저장과 후속 상담으로 이어질 만큼 구체적인가에 둔다.
