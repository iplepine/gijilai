# 상담/문진해설 프롬프트 비포 애프터

마지막 갱신일: 2026-05-04

## 목적

로드맵 목표 `G-001-paid-conversion-trust`에서 상담 결과의 핵심은 사용자가 "내 상황을 알아봤다"와 "오늘 바로 해볼 수 있다"를 느끼는 것이다. 이 문서는 상담 결과 전체와 문진해설(`questionAnalysis`)의 프롬프트/결과가 튜닝 전후로 어떻게 바뀌었는지 기록한다.

개인정보 보호를 위해 실제 계정 식별 정보는 넣지 않고, 로컬 eval의 익명화 케이스명과 짧은 결과 발췌만 사용한다.

## 1. 상담 결과 전체

상담 결과 전체는 `magicWord`, `actionItems`, `interpretation`, `chemistry`를 포함한다. 이번 튜닝의 가장 큰 변화는 실천 항목을 "괜찮은 조언"에서 "문제가 시작되는 순간에 바로 바꿔 끼울 1문장/1동작"으로 좁힌 것이다.

### 프롬프트 Before

Before 프롬프트도 이미 기본적인 품질 기준은 있었다.

- `actionItems`는 정확히 3개
- `actionItems[0]`은 기본 추천안
- Tiny Habits, If-Then, 30초 이내 행동 권장
- "칭찬하기", "공감하기", "대화하기" 같은 추상 제목 금지

하지만 빠져 있던 것이 있었다.

- 반복 요구를 강화하지 말라는 명시가 약함
- 이미 부모가 시도했지만 효과가 약했던 반응을 대체하라는 지시가 약함
- 차 안, 잠들기 전, 공공장소 같은 장면 제약이 약함
- 실천 `action`에 실제 말/동작이 빠져도 통과될 수 있음
- 후속 상담에서 이전 실천을 그대로 반복하는 문제를 충분히 막지 못함

### 결과 Before

차 안에서 같은 노래를 반복 요구하는 케이스에서 Before 결과는 사용자가 원하는 것을 그대로 키워주는 방향으로 나왔다.

```text
magicWord:
차에 탈 때, '네잎클로버 노래 100번 틀어줄게!'라고 말해보세요.

actionItems:
1. 차에 탈 때, 노래 미리 틀어주기
2. 노래가 끊길 때, 함께 다른 노래 찾기
3. 차에 탔을 때, 아이의 감정 공감하기
```

문제:

- "100번 틀어줄게"는 반복 요구를 그대로 강화한다.
- "원하는 노래를 미리 틀어주기"는 첫 실천으로는 너무 수동적이다.
- 차 안에서 "안아주기" 같은 처방은 주행 중일 수 있어 장면 제약과 맞지 않는다.
- "함께 다른 노래 찾기"는 운전 중 기기 조작을 늘릴 수 있다.

### 프롬프트 After

After 프롬프트는 상담 결과 전체에 아래 가드를 추가했다.

- **마찰 대체 원칙**: 이미 반복했지만 효과가 약한 반응을 더 하라고 하지 않고, 같은 순간에 바꿔 끼울 1문장/1동작을 제시한다.
- **문제 강화 금지**: 반복 요구, 한 가지 방식 고집, 대본 유지가 고민이면 무제한 제공이나 완전한 대본 맞추기를 기본안으로 두지 않는다.
- **장면 제약 반영**: 식당, 차 안, 잠들기 전, 공공장소에서는 실제 가능한 행동만 제안한다.
- **첫 실천 타이밍**: 첫 실천은 사건 뒤 칭찬/회고가 아니라 문제가 시작되는 순간의 마찰을 낮추는 행동이어야 한다.
- **실제 action 강제**: "~해보자고 물어보기", "~정하기" 같은 메타 설명 대신 실제 말 1문장 또는 손/시선/표시 동작을 넣는다.
- **상황별 좋은 예시**: 차 안 반복 노래, 식당 기다림, 손톱 물어뜯기, 대본형 역할놀이 예시를 직접 넣었다.

또한 처방 API temperature를 `0.7`에서 `0.45`로 낮췄다. 상담 결과는 창의적인 말맛보다 지시 준수와 안전성이 더 중요하기 때문이다.

### 결과 After

같은 차 안 반복 노래 케이스에서 After 결과는 요구를 인정하되 경계와 다음 순서를 보여주는 방향으로 바뀌었다.

```text
magicWord:
네잎클로버 노래는 좋아! 오늘은 한 번만 틀어보자.

actionItems:
1. 차 타기 전, 첫 곡 순서 정하기
   action: 출발 전에 '처음 한 번은 네잎클로버, 그다음은 조용히 가기'라고 말하고 손가락 1개를 보여주기

2. 노래가 끊길 때, 안전 신호 말하기
   action: '끊겼어. 아빠가 안전할 때 한 번 눌러줄게'라고 말하고 운전에 시선 두기

3. 차 안에서 울 때, 손가락으로 기다림 표시하기
   action: 손가락 하나를 세우며 '잠깐 기다리자'라고 말하기
```

개선:

- 반복 요구를 무제한 약속하지 않는다.
- 차에 타기 전 기대치를 먼저 맞춘다.
- 운전 중에는 아이를 안거나 기기 조작을 늘리지 않는다.
- 아이가 바로 볼 수 있는 손가락 표시를 넣어 실행 단위가 작아졌다.

## 2. 문진해설

문진해설은 이번 튜닝에서 가장 많이 바뀐 영역이다. Before는 답변마다 기질/감정을 해석하려는 힘이 강했고, After는 "이 처방이 왜 나왔는지 납득시키는 근거"로 역할을 재정의했다.

### 프롬프트 Before

Before 문진해설 프롬프트의 핵심 구조:

```text
각 문진 질문과 양육자의 답변을 기질 관점에서 해설하세요.
해설은 답변의 구체 장면/표현을 먼저 짚고, 그 다음에 기질 또는 발달적 가능성을 연결하세요.
한 답변에서 기질 포인트는 1개만 잡으세요.
답변만으로 근거가 약하면 발달적 맥락/상황 해석 수준에서 설명하세요.
```

문제:

- 문진해설의 목적이 "기질 관점 해설"로 잡혀 있어 모든 답변에 기질 라벨을 붙이려는 압력이 생겼다.
- "가끔 발생한다", "차를 타기 시작할 때", "물어본 적 없어" 같은 정보성 답변에도 감정/기질을 과잉 추론했다.
- 부모 반응을 평가하는 표현이 섞였다.
- 문진해설이 actionItems로 자연스럽게 이어지지 않는 경우가 있었다.

### 결과 Before

차 안 반복 노래 케이스:

```text
A: 가끔 발생한다
분석: 노래가 끊기는 상황이 가끔 있다는 것에서, 아이가 그 노래에 대한 의존도가 높고, 정서적으로 그 노래에 안정을 느낀다고 볼 수 있습니다.
```

```text
A: 딱히 없어
분석: 양육자님이 다른 방식으로 해결하려고 하지 않았다는 것은, 아이의 요구가 강하게 작용하고 있음을 나타냅니다.
```

손톱 물어뜯기 케이스:

```text
A: 물어본적 없어
분석: 양육자가 아이의 감정을 물어본 적이 없다는 것은, 아이가 자신의 감정을 표현할 기회가 부족하다는 것을 시사합니다.
```

문제:

- "가끔 발생한다"는 빈도 정보인데 정서적 안정/의존으로 과잉 해석했다.
- "딱히 없어"를 부모가 해결을 안 한 것처럼 읽을 수 있다.
- "물어본 적 없어"를 부모가 기회를 주지 못한 것처럼 들리게 만들었다.

### 프롬프트 After

After 문진해설 프롬프트는 목적과 금지선을 다시 잡았다.

```text
이 섹션의 목적은 기질 라벨을 붙이는 것이 아니라,
이 처방이 왜 나왔는지 양육자가 납득하도록 근거를 보여주는 것입니다.
```

핵심 변경:

- **구조 변경**: `답변 속 장면/표현 → 아이의 필요나 상황이 작동하는 방식 → 처방 방향 힌트`
- **문항별 근거 제한**: 해당 문항의 answer에 직접 포함된 단서만 우선 사용한다.
- **기질 라벨 선택 사항**: 모든 답변에 자극추구/위험회피/사회적민감성/인내력을 붙이지 않는다.
- **감정 단정 금지**: 중립 관찰/빈도/시점 답변만으로 불안, 스트레스, 강한 욕구, 안정감 욕구를 단정하지 않는다.
- **정보 해석 문장 추가**: 중립 답변은 "이 답변은 ... 정보를 줍니다"처럼 시작한다.
- **부모 탓 금지**: "기회를 놓쳤다", "부족하다", "과정이 설계되지 않았다" 금지
- **아이 결핍 표현 금지**: "인내가 부족하다", "참을성이 없다", "감정 조절이 안 된다" 금지

프롬프트만으로 100% 막기 어려운 변형 표현이 있어서, 생성 후 `consultPrescriptionGuardrails`로 한 번 더 정리한다.

### 결과 After

차 안 반복 노래 케이스:

```text
A: 가끔 발생한다
분석: 이 답변은 "가끔 발생한다"라는 정보를 줍니다. 이 문항만으로 감정이나 기질을 단정하기보다, 실제로 문제가 시작되는 순간에 아이가 바로 이해할 수 있는 짧은 말이나 눈에 보이는 신호를 붙이는 방향이 적합합니다.
```

```text
A: 딱히 없어
분석: 이 답변은 "딱히 없어"처럼 아직 다른 방식을 비교해본 자료가 적다는 뜻입니다. 양육자님의 대응을 평가하기보다, 다음번에는 아이가 바로 이해할 수 있는 짧은 말이나 눈에 보이는 신호를 하나 정해보는 방향이 적합합니다.
```

손톱 물어뜯기 케이스:

```text
A: 물어본적 없어
분석: 이 답변은 "물어본적 없어"처럼 아직 아이가 그 행동을 어떤 느낌으로 경험하는지 확인되지 않았다는 뜻입니다. 이 경우에는 기질을 단정하기보다, 다음번에 아이가 대답하기 쉬운 말로 감각이나 상황을 확인해보는 방향이 적합합니다.
```

개선:

- 정보성 답변을 감정/기질로 과잉 번역하지 않는다.
- 부모의 대응을 평가하지 않는다.
- 해설 끝이 "그래서 어떤 처방 방향인가"로 이어진다.

## 3. 후처리 가드레일

프롬프트를 강화해도 모델은 가끔 금지 표현의 변형을 만든다. 그래서 `app/src/lib/consultPrescriptionGuardrails.ts`를 추가했다.

가드레일이 보정하는 패턴:

- `물어본 적 없어` 같은 약한 답변이 부모 탓으로 바뀌는 경우
- `가끔 발생한다`, `차를 타기 시작할 때` 같은 중립 답변이 불안/욕구 단정으로 바뀌는 경우
- `인내가 부족하다`, `기회를 놓쳤다` 같은 평가 표현
- 차 안에서 안아주기, 운전 중 기기 조작 늘리기
- 사건 뒤 칭찬만 남은 실천 항목
- 차 안 반복 노래 실천이 메타 설명으로 끝나는 경우

## 4. 평가 변화

점수만 보면 Before도 5개 케이스가 모두 pass였지만, 사람이 읽었을 때 위험한 문장이 있었다. 이번 튜닝은 단순 점수 상승보다 **실제 부모에게 보여줘도 되는 문장 품질**을 안정시키는 목적이 크다.

| 항목 | Before | After |
|---|---|---|
| 반복 요구 케이스 | "100번 틀어줄게"처럼 문제 강화 가능 | 한 번 인정 후 다음 순서/경계 제시 |
| 차 안 실천 | 안아주기/다른 노래 찾기 등 장면 제약 약함 | 안전 신호, 운전에 시선, 손가락 표시 |
| 문진해설 | 답변마다 기질/감정 해석 압력 | 처방 근거 설명으로 역할 변경 |
| 약한 답변 | 부모가 기회를 주지 못한 듯 들림 | 아직 확인되지 않은 정보로 처리 |
| 중립 답변 | 불안/안정감/욕구 단정 | 정보 해석 후 추가 관찰/실천 방향 |
| 안전장치 | 프롬프트 의존 | 프롬프트 + 후처리 가드레일 |

## 5. 남은 주의점

- After 문진해설은 과잉 해석을 줄인 대신 일부 문장이 더 담백해졌다. 와우 포인트는 `interpretation`, `chemistry`, `magicWord`, 첫 실천에서 보강해야 한다.
- 가드레일은 위험 패턴을 줄이는 안전장치이지, 좋은 상담문을 새로 쓰는 엔진은 아니다. 반복 실패가 보이면 프롬프트 예시와 eval 케이스를 계속 추가해야 한다.
- 실제 사용자 데이터 기반 케이스는 계속 `cases.local.json`에만 두고, 문서에는 익명화된 짧은 발췌만 남긴다.
